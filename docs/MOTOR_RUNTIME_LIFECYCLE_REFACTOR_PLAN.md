# 모터 실행 상태 구조 개선 계획

## 문서 상태

- 작업명 · 모터 연결·검색·재시작 구조 개선
- 상태 · 구현 및 검증 완료
- 작성일 · 2026-07-28
- 완료일 · 2026-07-28
- 현재 조치 · 독립 실행 대상·단일 작업 상태·실제 복구 검증 적용
- 코드 구조 변경 · `motion_web_bridge`와 Web UI 범위에서 완료

## 확인된 근본 원인

- 이전 구조 정리는 Motor Manager 서비스 분리와 `execution_context` 도입까지 진행됐다.
- 프로젝트 파일 적용은 `execution_context`가 관리하지만 Motor Manager의 시작·정지·검색·복구는 별도 경로가 관리한다.
- 선택 프로젝트, 적용 프로젝트, 프로세스 환경변수, systemd 상태와 ROS 모터 상태에 단일 최종 책임자가 없다.
- 프로젝트를 변경하면 `applied_project_id`가 삭제되지만 이전 프로젝트로 실행 중인 Motor Manager는 함께 전환되지 않는다.
- AC Servo 검색은 Motor Manager를 정지한 뒤 `systemctl start` 요청 성공을 실제 복구 성공으로 오인할 수 있다.
- 적용 설정이 없을 때 Motor Manager 진입점이 성공 코드로 종료되어 systemd가 실패로 판단하지 않는다.
- 개별 API와 UI 테스트가 명령 호출 및 응답을 주로 확인하여 서비스 생존과 새 모터 상태 수신 실패를 잡지 못했다.

## 개발 목표

- 기존 `execution_context`를 프로젝트와 모터 실행 상태의 단일 조정기로 확장한다.
- 새로운 병렬 상태 관리 계층을 추가하지 않는다.
- 프로젝트 선택·설정 적용·AC Servo 검색·모터 재시작·복구가 같은 상태와 검증 절차를 사용하게 한다.
- `systemctl` 명령 성공이 아니라 실제 서비스·노드·설정·모터 상태를 기준으로 성공을 확정한다.
- 모든 비동기 작업은 제한시간 안에 `완료` 또는 `실패`로 종료하며 무기한 진행 상태를 허용하지 않는다.

## 불변조건

1. 선택 프로젝트와 실제 실행 프로젝트를 별도로 관리한다.
2. 프로젝트 선택만으로 실제 실행 프로젝트 기록을 삭제하거나 변경하지 않는다.
3. 선택 프로젝트와 실행 프로젝트가 다르면 모든 모터 명령을 차단한다.
4. 설정 적용 작업만 실제 실행 프로젝트를 변경할 수 있다.
5. 실행 성공은 다음 조건을 모두 만족해야 한다.
   - `motion-motor.service` active
   - `motor_manager_node` 존재
   - ROS `config_file` 파라미터가 적용 대상과 일치
   - 적용 설정 SHA-256 일치
   - 작업 시작 이후 새 `/motion_control/motor_status` 수신
   - 설정 대상 축 연결 결과 확인
6. AC Servo 검색은 검색 전 실제 실행 설정을 보존하고 같은 설정으로 복구한다.
7. 검색 전 Motor Manager가 정지 상태였다면 검색 후 임의로 시작하지 않는다.
8. 취소 또는 화면 이탈이 EtherCAT 복구 절차를 중단시키지 않는다.
9. 브라우저는 작업 성공 여부를 추측하지 않고 백엔드의 단일 작업 상태만 표시한다.
10. 프로젝트별 데이터와 실행 상태를 다른 프로젝트의 기본값으로 사용하지 않는다.

## 상태 모델

- `unconfigured` · 적용 가능한 모터 설정 없음
- `apply_required` · 선택 설정과 실행 설정 불일치
- `starting` · Motor Manager 시작 및 검증 중
- `running` · 설정·서비스·ROS 상태 일치
- `scanning` · EtherCAT 소유권 해제 후 물리 검색 중
- `restoring` · 검색 전 실행 설정 복구 중
- `failed` · 시작·검색·복구 실패

동시에 하나의 모터 실행 작업만 허용한다. 각 작업은 `operation_id`, 종류, 단계, 시작 시각, 제한시간과 오류를 기록한다.

## 정상 처리 흐름

### 프로젝트 선택

1. 진행 중인 모션·검색·적용 작업 확인
2. 선택 프로젝트와 프로젝트 세대 변경
3. 상위 실행 컨텍스트 무효화
4. 기존 실행 프로젝트와 Motor Manager 상태 유지
5. 선택·실행 프로젝트가 다르면 `apply_required`와 제어 차단 표시

### 모터 설정 적용

1. 선택 프로젝트 설정 및 프로젝트 격리 검증
2. 변경 불가능한 런타임 설정 사본과 SHA-256 생성
3. 적용 작업 생성 및 모터 명령 차단
4. Motor Manager 정지 확인
5. 새 설정을 적용 대상으로 기록하고 서비스 시작
6. 서비스·ROS 노드·설정 경로·SHA-256·새 모터 상태 검증
7. 검증 성공 후 실행 프로젝트 확정
8. 실패 시 성공으로 표시하지 않고 이전 설정과 오류 보존

### AC Servo 검색

1. 실제 실행 설정과 연결 축을 스냅샷으로 보존
2. 모션 정지와 제어 차단 확인
3. Motor Manager 정지 및 EtherCAT 소유권 해제 확인
4. `docs/MOTOR_SCAN_CONTRACT.md`에 따라 물리 검색
5. 검색 전 실행 상태에 따라 동일 설정 복구 또는 정지 유지
6. 복구가 필요한 경우 전체 실행 성공 조건 재검증
7. 검색과 복구 결과를 별도로 기록하고 최종 상태 확정

### 모터 제어 재시작

1. 확정된 실행 설정 존재 여부 확인
2. 다른 모터 실행 작업이 없는지 확인
3. 같은 실행 설정으로 Motor Manager 재시작
4. 전체 실행 성공 조건 검증
5. 제한시간 초과 또는 불일치 시 `failed` 확정

## 데이터 구조 방향

`selected_project`는 편집 대상을, `motor_runtime`은 모터 실행 목표와 작업 상태를 관리한다.

`motor_runtime` 필수 정보:

- 적용 대상 프로젝트 ID
- 런타임 설정 파일
- 설정 SHA-256
- 실행 컨텍스트 ID
- 프로젝트 세대
- 작업 ID·종류·단계
- 시작 시각·제한시간
- 마지막 오류

파일 기록만으로 실제 실행을 확정하지 않는다. systemd 및 ROS 상태와 교차 검증한다.
