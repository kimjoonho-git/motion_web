# 멀티 PC 동기 실행 개발안

- 문서 상태: 방향성 검토 기준
- 현재 코드 기준: 2026-08-04
- 현재 구현: 네트워크 고수준 실행·상위 제어권·절대시각 동기 반복 코드 완료 · 실물 미검증
- 선행 조건: 네트워크 PC 상태 공유·인증·참여 모드의 2대 PC 검증 완료
- 파일명은 기존 참조 호환을 위해 유지한다.
- 본 문서는 일반 일정 스케줄러가 아니라 최소 범위의 동시 시작·동기 반복만 다룬다.

## 문서 결론

- 현재 로컬 자동 반복을 원격으로 시작하거나 그대로 동기 실행에 재사용하지 않는다.
- `motion_coordination_node`는 인증·참여·제어권·공통 시각만 관리한다.
- 예약 시각 대기와 실제 로컬 재생은 `motion_run_manager`가 담당한다.
- 모터 명령 충돌과 긴급정지는 기존 `motion_supervisor`가 최종 차단한다.
- 첫 구현은 2대 PC의 1회 동시 시작으로 제한하고, 반복은 시작 오차 검증 후 추가한다.
- 10ms 이하 시작 오차는 목표값이며 실물 측정 전에는 달성으로 보고하지 않는다.

## 1. 목적

같은 내부망의 여러 컴퓨터가 서로 다른 로컬 프로젝트와 모션 파일을 사용하면서
모션을 같은 시각에 시작하고, 반복 실행도 같은 주기 경계에서 시작하게 한다.

모션마다 재생시간이 다르면 참여 컴퓨터 중 가장 긴 모션시간을 공통 반복 주기의
기준으로 사용한다.

## 2. 다른 기능과의 경계

| 기능 | 책임 |
|---|---|
| 로컬 자동 반복 | 한 컴퓨터가 자기 모션을 독립적으로 반복 |
| 네트워크 PC 연동 | 연결, 인증, 상태 공유, 참여 모드와 명령 전달 |
| 멀티 PC 동기 실행 | 상위 모션 실행 제어권, 공통 시작 시각과 반복 주기 |

- 네트워크 통신 계약은 `NETWORK_PC_COORDINATION_PLAN.md`를 사용한다.
- 본 기능은 `네트워크 PC 연동`을 대체하거나 중복 구현하지 않는다.
- 네트워크 연동과 본 기능은 동일한 `motion_coordination_node`에서 실행하되
  내부 모듈과 테스트를 분리한다.
- 네트워크 연결·인증·상태 연동을 먼저 구현하고 검증한 뒤 본 기능을 활성화한다.
- 날짜별 일정, 일일 운영시간, 이벤트 편집, 여러 모션 순서표는 구현하지 않는다.
- 각 컴퓨터의 프로젝트, 모션 파일, 모션축 설정과 모터 설정은 공유하지 않는다.
- 중앙 컴퓨터는 모션 위치값이나 모션 파일을 다른 컴퓨터에 전송하지 않는다.

### 현재 로컬 실행 기반

현재 `motion_run_manager`에는 다음 기반이 구현되어 있다.

- 프로젝트 세대와 실행 컨텍스트 검증
- 모션 파일·모션축 설정 SHA-256 검증
- `초기 위치 이동 → 상대 카운트다운 → 모션 재생` 단일 실행 순서
- 20ms 로컬 재생 주기
- 1회 실행과 `direct`, `dwell`, `reinitialize` 로컬 자동 반복
- Supervisor의 `playback`, `midi`, `manual` 명령 소유권 충돌 차단

현재 상대 카운트다운과 로컬 반복은 UTC 절대시각, 다른 PC의 최장 모션시간 및
공통 반복 번호를 알지 못한다. 따라서 동기 실행 완료로 간주하거나 멀티 PC 실행
엔진으로 직접 사용하지 않는다.

### 실행 책임 경계

```text
motion_coordination_node
  연결·인증·참여·상위 실행 제어권·공통 시작 시각 계산
        ↓ 예약 실행 요청
motion_run_manager
  실행 스냅샷·초기 위치 이동·절대시각 대기·로컬 파일 재생
        ↓ 기존 playback 통로
motion_supervisor
  명령 소유권·긴급정지·안전 차단
        ↓
motion_system
  실제 모터 통신·제어
```

`motion_coordination_node`는 모터 위치값, 모션 프레임 또는 Servo 명령을 직접
발행하지 않는다.

## 3. 모션 실행 제어권

모션 실행 제어권은 다음 두 단계로 구분한다.

```text
하위 제어권
각 컴퓨터의 1회 실행·로컬 자동 반복

상위 제어권
멀티 PC 동기 실행의 준비·동시 시작·반복·정지
```

- 한 컴퓨터는 하위 또는 상위 모션 실행 제어권 중 하나만 소유한다.
- 상위 제어권 획득은 `motion_coordination_node`가 현재 로컬 실행, 자동 반복 및
  자동 반복 재개 대기를 확인한 뒤 하나의 lease로 원자적으로 처리한다.
- `motion_run_manager`는 전달받은 lease ID와 만료시각이 일치할 때만 예약 실행과
  다음 반복을 허용하며, 별도 상위 제어권 원본을 저장하지 않는다.
- 상위 제어권은 `모션 실행`에만 적용한다.
- 모션 스튜디오, 파일 관리, 상태 확인, 오류 확인과 설정 화면을 전역 차단하지 않는다.
- 같은 모터에 대한 조그, 위치 이동, Servo OFF 등 동시 구동 명령은 기존
  `motion_run_manager`와 `motion_supervisor` 안전조건으로 차단한다.
- 긴급정지와 안전 정지는 제어권보다 항상 우선한다.

## 4. 기존 로컬 자동 반복과의 관계

- 현재 구현된 자동 반복은 하위 제어권의 로컬 기능이다.
- 멀티 PC 동기 실행은 로컬 자동 반복을 원격으로 켜는 기능이 아니다.
- 상위 제어권을 획득하면 로컬 자동 반복 설정은 삭제하거나 변경하지 않는다.
- 상위 제어권 동안 로컬 자동 반복 시작과 1회 실행만 거부한다.
- 상위 제어권 반환 후 로컬 자동 반복을 임의로 자동 재개하지 않는다.
- 사용자가 하위 제어권에서 로컬 자동 반복을 다시 시작할 수 있다.
- 로컬 자동 반복이 실행 중이면 해당 컴퓨터는 상위 제어권 준비를 거부한다.
- 프로그램 재시작 후 로컬 자동 반복 재개가 예약된 컴퓨터도 상위 준비를 거부한다.

## 5. 참여 조건과 공유 정보

각 컴퓨터는 로컬에서 다음 항목을 검사한다.

- 연동 모드가 `연동 참여`인지 확인.
- 등록된 최종 모션 파일과 모션축 설정 확인.
- 모션 파일과 매핑 파일 무결성 확인.
- 모터 연결, Servo 오류와 안전조건 확인.
- 전체 초기 위치 이동 가능 여부 확인.
- 로컬 자동 반복 또는 다른 모션 실행 여부 확인.
- 동기 반복을 요청한 경우에만 반복 연결부의 연속재생 안전조건 확인.

중앙 컴퓨터에는 다음 축약 정보만 전달한다.

- 컴퓨터 식별자.
- 준비 완료 또는 거부와 거부 사유.
- 로컬 모션 재생시간.
- 초기 위치 이동 예상시간 또는 준비 제한시간.
- 실행 상태, 시작·종료시각과 오류 상태.
- `network_operation_id`, 실행 세션과 상태 순번.

프로젝트명, 모션 파일명, 모션 데이터, Motion ID와 모터 설정값은 공유하지 않는다.

## 6. 공통 시작과 반복 주기

공통 반복 주기는 다음과 같이 계산한다.

```text
공통 반복 주기 = 참여 PC의 최장 모션시간 + 공통 대기시간
```

- 공통 대기시간 기본값은 `0초`다.
- 계산 결과는 모션 실행 주기인 20ms 단위로 올림한다.
- 모든 컴퓨터는 동기화된 UTC 절대시각을 사용한다.
- 중앙 컴퓨터는 초기 위치 이동과 통신 지연을 고려한 미래 시작 시각을 지정한다.
- 짧은 모션은 재생 완료 후 마지막 목표값을 유지하고 다음 공통 시작 시각까지 기다린다.
- 다음 반복은 이전 완료 메시지가 아니라
  `최초 시작 시각 + 반복 번호 × 공통 반복 주기`로 시작한다.
- PC 간에 모션 프레임이나 위치값을 실시간 전송하지 않는다.

### 예약 실행 계약

`START_AT`은 다음 값을 포함한다.

- `network_operation_id`
- `sender.coordination_boot_id`
- `program_session_id`
- `sequence`
- 반복 번호
- UTC 절대 시작 시각
- 공통 반복 주기
- 실행 스냅샷 ID
- 명령 만료 시각

각 컴퓨터는 UTC 시작 시각을 로컬 monotonic 기준 시각으로 한 번 변환하고 같은
기준으로 대기한다. 명령이 최소 선행시간보다 늦게 도착하거나 시간 동기화 오차가
허용 범위를 넘으면 시작하지 않고 `NOT_READY` 또는 `CANCELLED`을 반환한다.

반복 시작은 중앙 컴퓨터의 매회 HTTP 요청이 아니라 다음 식으로 계산한다.

```text
반복 N 시작 = 최초 monotonic 시작 기준 + N × 공통 반복 주기
```

네트워크 하트비트와 `NETWORK_PC_COORDINATION_PLAN.md`에서 정의한 상위 제어권
lease가 유효할 때만 다음 반복을 시작한다. 실행 중 시간 동기화 오차가 허용값을
넘으면 현재 주기 완료 후 다음 반복을 시작하지 않는다.

예:

```text
PC A 모션: 7초
PC B 모션: 9초
PC C 모션: 12초
공통 대기시간: 3초

공통 반복 주기: 15초
```

## 7. 실행 절차

```text
1. 중앙 컴퓨터가 참여 PC에 PREPARE 요청
2. 각 PC가 로컬 검사 후 재생시간과 READY / NOT_READY 보고
3. 중앙 컴퓨터가 최장 모션시간과 공통 반복 주기 계산
4. 중앙 컴퓨터가 상위 모션 실행 제어권 요청
5. 각 PC가 실행 스냅샷 고정 후 전체 초기 위치 이동
6. 각 PC가 ARMED 보고
7. 전체 ARMED 확인 후 중앙 컴퓨터가 START_AT 전달
8. 각 PC가 동일한 UTC 시각에 로컬 모션 파일 재생
9. 짧은 모션은 마지막 목표값을 유지
10. 다음 공통 주기에서 동시에 반복
```

- 준비 제한시간 전에 한 컴퓨터라도 실패하면 시작 전 전체 작업을 취소한다.
- 현재 실행은 준비 완료 시점에 고정한 파일·설정 스냅샷을 사용한다.
- 실행 중 변경된 설정은 다음 `PREPARE`에서 다시 검사한다.
- 반복마다 네트워크 시작 명령을 새로 보내지 않고 각 컴퓨터가 공통 절대시각을 계산한다.

## 8. 반복 안전조건

초기 최소 구현에서는 연속재생 안전검사를 통과한 모션만 동기 반복에 사용한다.

- 마지막 목표값과 첫 목표값의 연결부를 기존 연속재생 안전기준으로 검사한다.
- 안전기준을 통과하지 못하면 동기 반복 준비를 거부하고 원인을 표시한다.
- 반복 사이에 초기 위치 이동을 넣는 방식은 초기 최소 구현에서 제외한다.
- 반복 사이 초기 위치 이동을 추가할 경우 공통 주기는
  `모션시간 + 초기 위치 이동시간 + 대기시간`으로 별도 계산해야 한다.

## 9. 정지와 장애 처리

- `CANCEL_BEFORE_START`: 시작 전 준비·예약을 취소하고 상위 제어권을 반환.
- `STOP_AFTER_CYCLE`: 현재 공통 주기 완료 후 전체 반복 종료.
- `STOP_NOW`: 로컬 안전 정지 요청 후 다른 참여 PC에도 즉시 정지 전달.
- 긴급정지 또는 즉시 정지가 필요한 모터 오류: 해당 PC는 즉시 로컬 안전 정지하고
  중앙 컴퓨터는 전체 PC에 즉시 정지를 요청한다.
- 시작 전 참여 PC 실패: 전체 시작 취소.
- 중앙 컴퓨터 연결 끊김: 수락된 현재 주기까지만 완료하고 다음 반복 시작 금지.
- 참여 PC 연결 끊김: 연결된 PC에 장애를 표시하고 다음 반복 시작 금지.
- 연동 노드 오류: 로컬 웹과 Motor Manager는 유지하며 다음 반복만 금지.
- 프로그램 재시작: 상위 제어권과 준비 상태를 복원하지 않고 다시 준비해야 한다.
- 네트워크 실행 실패 후 로컬 자동 반복으로 자동 전환하지 않는다.

짧은 모션이 끝난 뒤 다음 공통 시작 시각까지 `motion_run_manager`는 `playback`
제어권을 유지하고 기존 재생 통로로 마지막 목표값을 20ms 주기에 맞춰 계속
갱신한다. 현재 로컬 `direct` 반복처럼 즉시 다음 회차를 시작하지 않는다. 실제
모터의 종료 위치 유지 여부는 실물 검증 항목이다.

## 10. 사용자 화면

`장비 연동 상태` 화면에서 다음 항목을 표시한다.

- 현재 모션 실행 제어권: `로컬` 또는 `네트워크 동기`.
- 네트워크 동기 실행: 준비 전, 준비 중, 시작 대기, 실행 중, 반복 대기, 정지 중, 오류.
- 참여 컴퓨터 수와 준비 완료 수.
- 공통 시작 시각.
- 최장 모션시간과 공통 반복 주기.
- 해당 컴퓨터의 로컬 모션시간과 다음 시작까지 남은 시간.
- 준비 거부, 실행 실패와 정지 사유.

다른 기능 버튼을 일괄 비활성화하지 않는다. 로컬 1회 실행이나 자동 반복 시작처럼
상위 모션 실행 제어권과 직접 충돌하는 동작만 실행 시 명확한 사유로 거부한다.

## 11. 시간 동기화

- 모든 참여 컴퓨터는 chrony 또는 동등한 시간 동기화를 사용한다.
- 목표 시작 오차는 10ms 이하로 두되 실제 다중 PC 측정 전에는 달성으로 보고하지 않는다.
- 준비 단계에서 시간 동기화 상태와 허용 오차를 검사한다.
- 시간 오차가 기준을 넘으면 해당 컴퓨터는 준비를 거부한다.
- 준비 결과에는 시간 동기화 출처, 측정 오차, 마지막 동기화 시각을 포함한다.
- 벽시계 변경이 예약 실행에 직접 영향을 주지 않도록 `START_AT` 수신 시 UTC를
  monotonic 기준으로 변환한 뒤 실행 중에는 같은 monotonic 기준을 사용한다.
- 시작 결과에는 요청 UTC 시각, 실제 로컬 시작 시각과 측정 오차를 기록한다.

## 12. 개발 순서

본 문서의 구현은 `NETWORK_PC_COORDINATION_PLAN.md`의 네트워크 상태 연동 단계가
완료된 뒤 시작한다. 두 기능을 동시에 개발하거나 한 번에 활성화하지 않는다.

0. 네트워크 PC 연동의 상태·인증·참여 모드 2대 PC 검증.
1. 로컬·네트워크 모션 실행 제어권 상태와 원자적 전환 계약 구현.
2. `PREPARE`, `READY`, `ARMED`, `START_AT`, `CANCEL_BEFORE_START`,
   `STOP_AFTER_CYCLE`, `STOP_NOW` 명령 계약 구현.
3. `motion_run_manager`에 실행 스냅샷 기반 예약 실행 API와 결과 기록 구현.
4. 2대 PC 1회 동시 시작과 10ms 목표 오차 측정.
5. 모션시간 수집과 최장 모션 기준 공통 주기 계산 구현.
6. 짧은 모션의 종료 위치 유지와 다음 공통 경계 대기 구현.
7. lease 만료, 정상 정지, 즉시 정지, 연결 단절과 프로그램 재시작 처리.
8. 2대 PC 동기 반복과 반복 누적 오차 검증.
9. 4대, 16대 PC 순서로 부하와 장애 검증.

## 13. 검증 기준

- 서로 다른 두 개 이상의 프로젝트에서 프로젝트 데이터가 섞이지 않는지 검증한다.
- 상위 제어권 중 로컬 1회 실행과 로컬 자동 반복만 충돌 사유로 거부되는지 검증한다.
- 상위 제어권 중 모션 스튜디오, 파일 관리, 상태·오류 확인이 유지되는지 검증한다.
- 긴급정지와 안전 정지가 제어권과 관계없이 동작하는지 검증한다.
- 최장 모션시간과 공통 대기시간으로 주기가 정확히 계산되는지 검증한다.
- 최소 선행시간보다 늦은 `START_AT`과 시간 동기화 오차 초과를 차단하는지 검증한다.
- 요청 UTC 시각과 각 PC의 실제 로컬 시작 시각을 기록하고 시작 오차를 계산하는지 검증한다.
- 짧은 모션이 종료 위치를 유지하고 공통 경계에서 다시 시작하는지 검증한다.
- 짧은 모션의 대기 중 마지막 목표값이 기존 재생 통로로 계속 갱신되는지 검증한다.
- 반복 횟수가 늘어나도 PC별 타이머 오차가 누적되지 않는지 검증한다.
- 중복·만료·순서 역전 명령이 중복 실행을 만들지 않는지 검증한다.
- 네트워크 단절과 프로그램 재시작 후 다음 반복이 시작되지 않는지 검증한다.
- `CANCEL_BEFORE_START`, `STOP_AFTER_CYCLE`, `STOP_NOW`가 서로 다른 시점과
  결과 상태로 처리되는지 검증한다.
- 로컬 자동 반복 설정이 변경되지 않고 상위 제어권 반환 후 자동 재개되지 않는지 검증한다.
- 코드 검증, 실행 검증과 다중 PC 실물 검증 결과를 구분하여 기록한다.

## 14. 현재 상태

- 현재 코드의 로컬 자동 반복은 하위 제어권 기능으로 구현되어 있다.
- 로컬 실행은 기존 상대 카운트다운을 유지하고 네트워크 동기 실행만 UTC 예약
  시각을 수신 즉시 monotonic 마감시각으로 변환한다.
- Supervisor의 기존 `playback` 소유권 위에 Web Bridge와 연동 노드의 상위
  실행 lease를 추가했으며 실제 모터 명령 통로는 변경하지 않았다.
- 네트워크 상태 송수신, 인증된 준비·실행 명령과 단절 만료 처리를 구현했다.
- 멀티 PC 동기 실행과 상위 모션 실행 제어권 코드는 구현되었다.
- HMAC 실행 명령, 영속 중복 작업 차단, 5초 lease, chrony 오차 검사,
  절대시각 반복 경계와 시작 오차 기록을 사용한다.
- 4·16·32대 자동 검증은 통신·계산 시뮬레이션이며 실제 네트워크와 모터는
  실물 미검증이다.
- 본 문서는 일반 다중 스케줄러가 아니라 최소 동기 실행 범위를 정의한다.
- 실제 2대 PC에서 초기 위치 이동시간, 10ms 시작 오차와 종료 위치 유지부터
  검증한 뒤 4·16·32대 순서로 실물 검증한다.
