# 다중 PC 모션 스케줄러 구조 계획

## 1. 목적

여러 대의 Ubuntu·ROS 2 PC가 서로 다른 모터와 로컬 모션을 사용하면서도,
공통 스케줄에 따라 중요 이벤트를 동기화하여 실행한다.

## 2. 전체 구조

- 모든 PC는 동일한 프로그램 구조를 사용한다.
- PC별 프로젝트, 레이어, 모션 파일, Motion ID, 모터축 설정은 달라도 된다.
- PC 간에 프로젝트 전체나 모션 파일 내용을 공유하지 않는다.
- PC 간 공유 대상은 스케줄, 제어 명령, 실행 상태, 모터 상태, 오류와 시간 정보이다.
- 각 PC는 공통 스케줄 이벤트를 자신의 로컬 모션에 연결한다.

## 3. 스케줄과 로컬 모션

공통 스케줄은 실제 모션 값이 아니라 이벤트와 시각을 관리한다.

예:

```text
반복 주기: 120초
PC1: GREETING -> local_motion_a, 예상 재생 120초
PC2: GREETING -> local_motion_b, 예상 재생 110초
PC3: GREETING -> local_motion_c, 예상 재생 115초
```

실행 규칙:

- 세 PC는 공통 예약 시각에 동시에 시작한다.
- PC2는 110초, PC3은 115초에 자신의 모션을 완료하고 대기한다.
- PC1은 120초에 완료한다.
- 다음 실행은 이전 완료 메시지가 아니라 고정된 절대시각을 기준으로 시작한다.
- 로컬 모션이 없는 PC의 이벤트 처리 규칙은 추후 결정한다.

## 4. 시간과 동기화

- 중요 예약 이벤트의 PC 간 시작 오차 목표는 10ms 이하이다.
- 동기화 대상은 초기화 이동 시작, 모션 시작, 반복 주기 경계 등의 중요 이벤트이다.
- 모션 재생 중 매 프레임을 PC 간에 전송하거나 강제로 맞추지 않는다.
- 각 PC의 로컬 모션 완료 시각은 다를 수 있으며, 실제 완료 시각을 관리 PC에 보고한다.
- PC 간 예약은 동기화된 UTC 절대시각을 사용한다.
- 운영시간 표시와 판단은 설치 지역의 현지 시간을 사용한다.
- 시간대는 `Asia/Seoul` 같은 IANA 지역 시간대로 저장하여 서머타임을 반영한다.
- 다른 시간대에 있는 PC는 별도 스케줄 그룹으로 관리한다.

## 5. 일일 운영 구간

- 하루에 여러 개의 운영 구간을 설정할 수 있다.
- 예: `09:00~12:00`, `15:00~22:00`.
- 운영 구간 밖에서는 새 모션을 시작하지 않는다.
- 운영 구간 종료 전에 시작한 모션은 종료 시각을 넘겨도 끝까지 재생한다.
- 예: 11:59에 시작한 2분 모션은 12:01에 완료한 뒤 15:00까지 대기한다.
- 예: 21:59에 시작한 2분 모션은 22:01에 완료한 뒤 일일 운영을 종료한다.
- 겹치는 운영 구간과 종료가 시작보다 빠른 설정은 저장하지 않는다.

## 6. 관리 PC

- 모든 PC는 관리 PC와 실행 PC 기능을 모두 가질 수 있다.
- 하나의 스케줄 그룹에서 실행 중인 활성 관리 PC는 한 대만 허용한다.
- 초기 구현에서는 사용자가 활성 관리 PC를 선택하는 방식을 우선 검토한다.
- 자동 마스터 선출과 장애 전환은 동시에 두 마스터가 생기지 않는 선출·임대 규칙을 정한 뒤 추가한다.

## 7. 기본 실행 흐름

```text
관리 PC -> PREPARE(schedule_id, schedule_version, run_id)
실행 PC -> READY / NOT_READY
관리 PC -> START_AT(UTC 절대시각)
실행 PC -> 예약 시각에 로컬 모션 시작
실행 PC -> STARTED / FINISHED / ERROR 보고
실행 PC -> 다음 예약 시각까지 대기
```

- 명령은 재전송되어도 중복 실행되지 않도록 `run_id`와 이벤트 순번을 사용한다.
- 실행 PC는 로컬 모션의 존재 여부와 예상 재생시간을 준비 단계에서 검사한다.
- 관리 PC는 PC별 예상 재생시간과 실제 시작·종료시각을 기록한다.

## 8. PC 간 공유 상태

상태를 하나의 문자열로 합치지 않고 항목별로 구분한다.

- 연결: 온라인, 오프라인, 응답 지연.
- 모터: 전체 ON, 전체 OFF, 일부 ON, 알 수 없음.
- 실행: 정지, 초기화 중, 준비 완료, 재생 중, 정지 처리 중.
- 스케줄: 운영 구간, 운영시간 대기, 다음 실행 대기.
- 오류: 정상, 경고, 오류, 비상정지.
- 현재 작업: `schedule_id`, `run_id`, 이벤트, 로컬 모션 키, 시작시각, 예상 종료시각, 진행률.
- 오류 상세: 오류 코드, 메시지, 발생시각, 관련 모터 또는 Motion ID.

`동작 중`은 초기화·복귀를 포함한 모터 움직임 전체를 의미하고,
`재생 중`은 스케줄에 연결된 로컬 모션 파일을 실행하는 상태로 구분한다.

## 9. 상태 통신 규칙

- 상태 변화는 즉시 관리 PC에 보고한다.
- 실행 중에는 주기적인 상태·하트비트를 전송한다.
- 모든 상태에 PC ID, UTC 시각, 순번을 포함한다.
- 일정 시간 응답이 없으면 응답 지연 또는 오프라인으로 표시한다.
- 시작, 정지, 초기화 명령은 수신·수행 결과를 응답한다.

## 10. 추후 결정 사항

- 모션 완료 후 대기: 마지막 위치 유지, 초기 위치 복귀, 서보 OFF.
- PC 또는 통신 실패 시 전체 스케줄의 계속·중단 규칙.
- 필수 PC와 선택 PC의 구분 및 일부 PC 미준비 시 시작 규칙.
- 로컬 모션이 없거나 예상 재생시간이 다른 경우의 처리.
- 자동 관리 PC 선출, 장애 전환, 임대시간, 스플릿 브레인 방지.
- PC 간 통신 방식, ROS 2 DDS 범위, 네트워크 접근 제한과 인증.
- 하트비트 주기, 오프라인 판정시간, 상태 갱신 주기.
- 요일별 운영시간, 휴무일, 특정일 예외 스케줄.

## 11. 현재 상태

- 본 문서는 확정된 큰 구조와 미결 사항을 기록한 설계 계획이다.
- 다중 PC 스케줄러와 상태 통신은 아직 구현하지 않았다.
- 추후 작업 재개 시 본 문서를 기준으로 상세 요구사항과 통신 계약을 확정한다.
