# 네트워크 PC 연동 개발안

## 1. 문서 목적

같은 내부망에 연결된 여러 컴퓨터가 각자의 프로젝트·모터·모션을 독립적으로
운영하면서 기본 상태를 공유하고, 사용자가 허용한 컴퓨터에만 제한적인 연동
제어를 수행하기 위한 개발 기준을 정의한다.

본 문서는 상태 공유와 모션 실행 연동의 우선 개발 기준이다.
`MULTI_PC_MOTION_SCHEDULER_PLAN.md`의 절대시각 스케줄 실행은 본 기능이 안정적으로
검증된 이후 진행하는 별도 확장 범위다.

## 2. 최우선 불변조건

- 네트워크 연동 상태와 관계없이 각 컴퓨터의 로컬 기능은 독립적으로 동작한다.
- 중앙 컴퓨터 종료, 네트워크 단절, 다른 컴퓨터 오류 및 연동 노드 오류가
  로컬 프로젝트·모터·모션 기능을 차단하지 않는다.
- 각 컴퓨터의 프로젝트, 모터 설정, 모션 파일과 모션축 설정은 서로 공유하지 않는다.
- 다른 컴퓨터 상태를 로컬 프로그램 정상 여부의 필수 조건으로 사용하지 않는다.
- 다른 컴퓨터가 로컬 안전조건을 해제하거나 우회할 수 없다.
- `motion_system`을 직접 수정하거나 컴퓨터 간 제어 통로로 사용하지 않는다.
- 컴퓨터 간 ROS 2 DDS 통신을 열지 않고 `ROS_LOCALHOST_ONLY=1`을 유지한다.

## 3. 지원 규모

- 권장 운영 수: 1~16대.
- 초기 최대 허용 수: 중앙 컴퓨터를 포함한 32대.
- 컴퓨터 수를 4대로 고정하지 않는다.
- 등록 수와 화면 목록은 동적으로 관리한다.
- 최대 허용 수는 설정으로 변경할 수 있게 하되 상태 형식은 컴퓨터 수에 의존하지 않는다.

## 4. 전체 구조

각 컴퓨터의 기존 웹에 `장비 연동 상태` 화면을 추가한다.
상태 송수신은 웹 프로세스와 분리된 `motion_coordination_node`가 담당한다.

```text
각 컴퓨터의 로컬 프로그램
        ↓ 로컬 상태
motion_coordination_node
        ↓ 내부망 HTTP
활성 중앙 motion_coordination_node
        ↓ 통합 상태
각 컴퓨터 기존 웹의 장비 연동 상태 화면
```

- 모든 컴퓨터에 `motion_coordination_node`를 설치한다.
- 연동 노드는 별도 프로세스와 별도 사용자 서비스로 실행한다.
- 서비스 가칭은 `motion-coordination.service`로 한다.
- 컴퓨터 내부 상태 전달에는 로컬 ROS를 사용할 수 있다.
- 컴퓨터 간 상태·제어 통신에는 내부망 HTTP를 사용한다.
- 연동 노드 실패가 웹, Supervisor, Motor Manager 실행에 영향을 주지 않게 한다.
- 별도의 사용자용 프로그램이나 바탕화면 아이콘은 추가하지 않는다.

## 5. 중앙 컴퓨터

- 여러 컴퓨터 중 어느 컴퓨터든 중앙 역할을 맡을 수 있다.
- 하나의 연동 구성에서 활성 중앙 컴퓨터는 한 대만 허용한다.
- 초기 구현에서는 사용자가 웹에서 중앙 컴퓨터를 수동으로 지정한다.
- 자동 중앙 선출과 자동 장애 전환은 초기 범위에서 제외한다.
- 중앙 역할 변경 시 이전 중앙의 권한이 해제된 것을 확인한 뒤 새 중앙을 활성화한다.
- 중앙 컴퓨터 종료 시 각 컴퓨터의 로컬 기능은 유지하고 새로운 연동 명령만 차단한다.

## 6. 컴퓨터별 연동 모드

각 컴퓨터 사용자가 해당 컴퓨터의 웹에서 직접 연동 모드를 선택한다.
중앙 컴퓨터가 다른 컴퓨터의 연동 모드를 강제로 변경할 수 없다.

| 모드 | 상태 전송 | 전체 상태 확인 | 제한 제어 수신 |
|---|---:|---:|---:|
| 연동 끔 | 안 함 | 안 함 | 차단 |
| 상태 공유 | 허용 | 허용 | 차단 |
| 연동 참여 | 허용 | 허용 | 로컬 검사 후 허용 |

- 연동 노드 프로세스는 계속 실행하고 연동 모드만 변경한다.
- `연동 참여`는 프로그램 재시작 후 `상태 공유`로 복귀하는 것을 기본 안전정책으로 검토한다.
- 동작 중 연동 해제는 로컬 동작 상태를 확인한 뒤 처리한다.

## 7. 공유 상태

컴퓨터 간에는 축약된 상태만 공유한다.

- 컴퓨터 식별자와 표시 이름.
- 프로그램 정상, 오류, 연결 끊김.
- 현재 연동 모드와 중앙 역할 여부.
- 모터 설정 미완료, 완료, 오류.
- 모션 실행 설정 미완료, 완료, 오류.
- 모터 연결 정상, 오프라인, 오류.
- 안전 정상 또는 차단.
- 초기위치 이동 가능, 이동 중, 완료, 실패.
- 모션 실행 가능, 동작 중, 완료, 실패.
- 모션 정지 중, 정지 완료.
- 실행 실패·거부 사유.
- 현재 `operation_id`.
- 프로그램 시작 세션을 구분하는 `boot_id`.
- 상태 순서를 구분하는 `sequence`.
- 마지막 상태 변경·수신 시각.

## 8. 공유하지 않는 데이터

- 프로젝트 ID와 프로젝트명.
- 프로젝트 파일과 프로젝트 선택 상태.
- 모터 설정값과 모터축 설정 파일.
- 모션 파일 내용과 모션축 매핑.
- 모션 스튜디오 레이어·포인트·편집 데이터.
- 실제 위치·속도·토크 명령값.
- 다른 컴퓨터의 로컬 파일 경로.

각 컴퓨터의 프로젝트가 서로 달라도 연동할 수 있으며 프로젝트 동일성은 비교하지 않는다.

## 9. 제어 대상

연동 제어는 모션 스튜디오가 아니라 `모션 실행`의 실제 구동 절차만 대상으로 한다.

모션 작업과 실제 실행의 역할은 다음과 같이 고정한다.

```text
모션 스튜디오
모션 생성 → 녹화 → 레이어·포인트 편집 → 미리보기 → 최종 모션 파일 저장
                                                        ↓
모션 실행
최종 모션 파일 선택 → 모션축 설정 확인 → 초기위치 이동 → 최종 파일 그대로 재생
```

- 모션 스튜디오는 모션 생성·편집·저장 영역이다.
- 모션 실행은 저장된 최종 모션 파일의 실제 구동 영역이다.
- 모션 실행은 최종 모션 파일과 적용된 모션축 설정만 사용한다.
- 모션 실행 중 MIDI 입력으로 모션값·속도·축 출력을 변경하지 않는다.
- 모션 실행 중 MIDI 시작·정지·선택 명령을 받지 않는다.
- MIDI 제어는 모션 스튜디오의 녹화·제작 영역에만 사용한다.
- 네트워크 연동은 실행 시작·정지 같은 고수준 요청만 전달하며 모션값을 전달하거나
  최종 모션 파일 내용을 변경하지 않는다.

| 연동 명령 | 로컬 실행 기능 |
|---|---|
| 실행 준비 확인 | 선택된 최종 모션·모션축 설정·모터·안전조건 확인 |
| 초기위치 이동 | 모션 실행의 초기위치 이동 |
| 초기위치 이동 정지 | 진행 중인 초기위치 이동 정지 |
| 모션 실행 | 미리 선택된 최종 모션 파일 실행 |
| 모션 정지 | 실행 중인 모션 정지 |
| 상태 다시 전송 | 현재 상태 즉시 갱신 |

- 중앙 컴퓨터는 위치값, 모션 파일명 또는 프로젝트 ID를 전달하지 않는다.
- 각 컴퓨터 사용자가 로컬 프로젝트에서 최종 모션 파일과 모션축 설정을 미리 선택한다.
- 원격 요청은 고수준 실행 요청이며 실제 실행 전 해당 컴퓨터가 로컬 안전조건을 다시 검사한다.
- 요청 결과는 수신, 검증 중, 승인, 거부, 실행 시작, 진행 중, 완료, 실패,
  사용자 취소 및 안전 차단으로 구분한다.

## 10. 연동에서 제외하는 제어

- 모션 스튜디오 녹화·편집·저장.
- 프로젝트 선택·변경.
- 모터 설정 수정·적용.
- 모터 검색.
- 모션 파일과 모션축 설정의 원격 선택.
- Servo ON/OFF.
- 프로그램 재시작과 모터 제어 재시작.
- 조그와 축별 위치 명령.
- Servo 오류 정책 변경.
- 긴급정지 해제와 안전 차단 해제.

모션 정지는 허용하지만 안전 차단 해제는 각 컴퓨터의 로컬 조작으로만 수행한다.

## 11. 기본 사용자 절차

1. 각 컴퓨터의 웹을 연다.
2. `장비 연동 상태`에서 연동 모드를 선택한다.
3. 한 컴퓨터를 중앙 역할로 지정한다.
4. 연동 참여 대상 컴퓨터를 확인한다.
5. 전체 준비 상태 확인을 요청한다.
6. 각 컴퓨터가 로컬 설정·모터·안전조건을 검사한다.
7. 초기위치 이동을 요청한다.
8. 필요한 컴퓨터의 초기위치 이동 완료를 확인한다.
9. 모션 실행을 요청한다.
10. 실행 진행 상태와 완료·오류를 확인한다.
11. 필요하면 개별 또는 전체 모션 정지를 요청한다.

## 12. 장애 처리

- 중앙 컴퓨터 종료: 로컬 기능 유지, 새로운 연동 명령 차단.
- 네트워크 단절: 로컬 기능 유지, 해당 컴퓨터를 연결 끊김으로 표시.
- 다른 컴퓨터 오류: 정상 컴퓨터의 로컬 기능에 영향 없음.
- 연동 노드 오류: 웹·Supervisor·Motor Manager 유지.
- 프로그램 재시작: 이전 완료 상태를 폐기하고 새 `boot_id`로 상태 재등록.
- 프로젝트·모션 선택 변경: 이전 초기위치 완료·모션 완료 상태 폐기.
- 상태 수신 중단: 초기 기준 3~5초 후 연결 끊김으로 판정.
- 순서가 뒤바뀐 상태: `boot_id + sequence`로 폐기.
- 중복 실행 요청: `operation_id`로 한 번만 실행.
- 모순 상태: 임의로 선택하지 않고 상태 충돌로 표시.

네트워크 단절만으로 로컬 프로그램 전체를 차단하지 않는다.
이미 수락된 로컬 동작은 해당 컴퓨터의 로컬 안전조건과 사용자 조작으로 관리한다.

## 13. 전역 설정

연동 설정은 프로젝트 데이터와 분리된 전역 설정으로 관리한다.

```text
config/motion_coordination.yaml
```

예상 항목:

```yaml
machine_id: machine-a
display_name: PC A
role: coordinator
mode: status
coordinator_url: http://172.16.21.10:8010
max_computers: 32
```

- `machine_id`는 컴퓨터별로 중복되지 않아야 한다.
- IP 주소는 고정 IP 또는 DHCP 예약을 권장한다.
- 연동 설정과 프로젝트 데이터 사이에 대체값·복사·병합 경로를 만들지 않는다.

## 14. 개발 순서

1. 축약 상태 계약과 `motion_coordination_node` 구현.
2. `연동 끔`, `상태 공유`, `연동 참여` 구현.
3. 중앙 역할 수동 지정과 중앙 중복 차단.
4. 기존 웹에 `장비 연동 상태` 화면 추가.
5. 상태 공유 전용 다중 컴퓨터 검증.
6. 모션 실행 준비 확인 연동.
7. 초기위치 이동·정지 연동.
8. 최종 모션 실행·정지 연동.
9. 1대, 4대, 16대, 32대 상태 부하 검증.
10. 네트워크 단절, 프로그램 재시작, 프로젝트 변경, 중앙 종료 검증.

## 15. 검증 기준

- 서로 다른 두 개 이상의 프로젝트로 프로젝트 데이터 격리를 검증한다.
- 컴퓨터별 프로젝트·모터·모션 설정이 다른 상태를 검증한다.
- 연동 끔·상태 공유·연동 참여를 각각 검증한다.
- 중앙 역할 중복과 중앙 전환 실패를 검증한다.
- 상태 지연·순서 역전·중복·오프라인을 검증한다.
- 연동 노드 종료 후 로컬 웹·모터·모션 기능이 유지되는지 검증한다.
- 초기위치 이동과 모션 실행 요청이 모션 스튜디오가 아닌 모션 실행 경로를
  사용하는지 검증한다.
- 자동 테스트, 다중 프로세스 실행 검증, 다중 PC 실물 검증을 구분해 기록한다.

## 16. 현재 상태

- 본 문서는 확정된 개발 방향을 저장한 계획 문서다.
- 네트워크 PC 상태 공유와 제한 제어는 아직 구현하지 않았다.
- 추후 작업 재개 시 본 문서를 기준으로 통신 계약과 UI 상세 요구사항을 확정한다.
