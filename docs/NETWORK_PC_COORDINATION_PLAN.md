# 네트워크 PC 연동 개발안

> 현재 코드 재검토 반영: 2026-07-29
> 기준 구조: 프로젝트 실행 컨텍스트, `motion_run_manager` 단일 실행 순서,
> 프로젝트별 자동 반복 설정, 상위 프로그램과 Motor Manager 분리 서비스

## 1. 문서 목적

같은 내부망에 연결된 여러 컴퓨터가 각자의 프로젝트·모터·모션을 독립적으로
운영하면서 기본 상태를 공유하고, 사용자가 허용한 컴퓨터에만 제한적인 연동
제어를 수행하기 위한 개발 기준을 정의한다.

본 문서는 상태 공유, 참여 권한, 인증, 명령 전달과 연결 장애 처리의 개발 기준이다.
여러 컴퓨터의 모션 시작 시각과 반복 주기를 결정하지 않는다.

`MULTI_PC_MOTION_SCHEDULER_PLAN.md`는 본 문서의 통신과 참여 기능을 사용하는
상위 `멀티 PC 동기 실행` 개발안이다. 두 문서의 책임은 다음과 같이 구분한다.

| 개발안 | 담당 책임 |
|---|---|
| 네트워크 PC 연동 | 연결, 인증, 상태 공유, 참여 모드, 명령 전달, 중복·만료 명령 차단 |
| 멀티 PC 동기 실행 | 실행 제어권, 전체 준비 확인, 공통 시작 시각, 최장 모션 기준 반복 |

현재 각 컴퓨터에 구현된 `로컬 자동 반복`은 위 두 기능과 분리된 하위 실행 기능이다.

## 2. 최우선 불변조건

- 네트워크 연동 상태와 관계없이 각 컴퓨터의 로컬 기능은 독립적으로 동작한다.
- 중앙 컴퓨터 종료, 네트워크 단절, 다른 컴퓨터 오류 및 연동 노드 오류가
  로컬 프로젝트·모터·모션 기능을 차단하지 않는다.
- 각 컴퓨터의 프로젝트, 모터 설정, 모션 파일과 모션축 설정은 서로 공유하지 않는다.
- 다른 컴퓨터 상태를 로컬 프로그램 정상 여부의 필수 조건으로 사용하지 않는다.
- 다른 컴퓨터가 로컬 안전조건을 해제하거나 우회할 수 없다.
- `motion_system`을 직접 수정하거나 컴퓨터 간 제어 통로로 사용하지 않는다.
- 컴퓨터 간 ROS 2 DDS 통신을 열지 않고 `ROS_LOCALHOST_ONLY=1`을 유지한다.

## 3. 지원 규모

- 권장 운영 수: 1~16대.
- 초기 최대 허용 수: 중앙 컴퓨터를 포함한 32대.
- 컴퓨터 수를 4대로 고정하지 않는다.
- 등록 수와 화면 목록은 동적으로 관리한다.
- 최대 허용 수는 설정으로 변경할 수 있게 하되 상태 형식은 컴퓨터 수에 의존하지 않는다.

## 4. 전체 구조

각 컴퓨터의 기존 웹에 `장비 연동 상태` 화면을 추가한다.
상태 송수신은 웹 프로세스와 분리된 `motion_coordination_node`가 담당한다.

```text
각 컴퓨터의 로컬 프로그램
        ↓ 로컬 상태
motion_coordination_node
        ↓ 내부망 HTTP
활성 중앙 motion_coordination_node
        ↓ 통합 상태
각 컴퓨터 기존 웹의 장비 연동 상태 화면
```

- 모든 컴퓨터에 `motion_coordination_node`를 설치한다.
- 연동 노드는 별도 프로세스와 별도 사용자 서비스로 실행한다.
- 서비스 가칭은 `motion-coordination.service`로 한다.
- 컴퓨터 내부 상태 전달에는 로컬 ROS를 사용할 수 있다.
- 컴퓨터 간 상태·제어 통신에는 내부망 HTTP를 사용한다.
- 연동 노드 실패가 웹, Supervisor, Motor Manager 실행에 영향을 주지 않게 한다.
- 별도의 사용자용 프로그램이나 바탕화면 아이콘은 추가하지 않는다.
- 기존 웹의 `/api/status` 전체 응답을 다른 컴퓨터로 전달하지 않는다.
- `motion_coordination_node`는 로컬 상태를 읽은 뒤 허용된 축약 상태만 새 객체로
  생성하여 전송한다.
- 다른 컴퓨터가 기존 모션 실행 API를 직접 호출하지 않게 하고 연동 전용 인증
  API를 사용한다.

### 4.1 노드와 내부 모듈 경계

네트워크 PC 연동과 멀티 PC 동기 실행은 별도 노드 두 개로 나누지 않고
`motion_coordination_node` 하나에서 관리한다. 연결 상태, 중앙 권한,
`network_operation_id`와 모션 실행 제어권을 한 노드가 소유하여 서로 다른
프로세스의 판단 불일치와 중복 실행을 방지한다.

노드 내부 구현은 다음 모듈로 분리한다.

```text
motion_coordination_node
├─ status_adapter
│  로컬 상태를 외부용 축약 상태로 변환
├─ network_transport
│  HTTP 통신·인증·재전송·중복 명령 차단
├─ peer_registry
│  참여 컴퓨터·하트비트·연결 상태 관리
├─ execution_ownership
│  하위·상위 모션 실행 제어권 관리
└─ synchronized_run
   전체 준비·공통 시작·동기 반복 관리
```

- 하나의 노드는 하나의 파일을 의미하지 않는다. 모듈과 테스트는 기능별로 분리한다.
- 초기 개발에서는 `synchronized_run`을 활성화하지 않고 네트워크 상태 연동만
  구현한다.
- 네트워크 상태 연동 검증이 완료된 뒤 같은 노드에 제어권과 동기 실행 모듈을
  단계적으로 활성화한다.
- 향후 일정 편집과 복잡한 다중 스케줄 기능이 추가되어 책임과 장애 범위가 커질
  때만 `synchronized_run`의 별도 노드 분리를 재검토한다.

## 5. 중앙 컴퓨터

- 여러 컴퓨터 중 어느 컴퓨터든 중앙 역할을 맡을 수 있다.
- 하나의 연동 구성에서 활성 중앙 컴퓨터는 한 대만 허용한다.
- 초기 구현에서는 사용자가 웹에서 중앙 컴퓨터를 수동으로 지정한다.
- 자동 중앙 선출과 자동 장애 전환은 초기 범위에서 제외한다.
- 중앙 역할 변경 시 이전 중앙의 권한이 해제된 것을 확인한 뒤 새 중앙을 활성화한다.
- 중앙 컴퓨터 종료 시 각 컴퓨터의 로컬 기능은 유지하고 새로운 연동 명령만 차단한다.

## 6. 컴퓨터별 연동 모드

각 컴퓨터 사용자가 해당 컴퓨터의 웹에서 직접 연동 모드를 선택한다.
중앙 컴퓨터가 다른 컴퓨터의 연동 모드를 강제로 변경할 수 없다.

| 모드 | 상태 전송 | 전체 상태 확인 | 제한 제어 수신 |
|---|---:|---:|---:|
| 연동 끔 | 안 함 | 안 함 | 차단 |
| 상태 공유 | 허용 | 허용 | 차단 |
| 연동 참여 | 허용 | 허용 | 로컬 검사 후 허용 |

- 연동 노드 프로세스는 계속 실행하고 연동 모드만 변경한다.
- `연동 참여`는 프로그램 재시작 후 `상태 공유`로 복귀하는 것을 기본 안전정책으로 검토한다.
- 동작 중 연동 해제는 로컬 동작 상태를 확인한 뒤 처리한다.

## 7. 공유 상태

컴퓨터 간에는 축약된 상태만 공유한다.

- 컴퓨터 식별자와 표시 이름.
- 프로그램 정상, 오류, 연결 끊김.
- 현재 연동 모드와 중앙 역할 여부.
- 모터 설정 미완료, 완료, 오류.
- 모션 실행 설정 미완료, 완료, 오류.
- 모터 연결 정상, 오프라인, 오류.
- 안전 정상 또는 차단.
- 초기위치 이동 가능, 이동 중, 완료, 실패.
- 모션 실행 가능, 동작 중, 완료, 실패.
- 모션 정지 중, 정지 완료.
- 실행 실패·거부 사유.
- 현재 `network_operation_id`.
- 연동 노드 실행 세션을 구분하는 `coordination_boot_id`.
- 상위 로컬 프로그램 실행 세션을 구분하는 `program_session_id`.
- 상태 순서를 구분하는 `coordination_sequence`.
- 마지막 상태 변경·수신 시각.

현재 로컬 실행 상태는 다음과 같이 세분화되어 있다.

```text
idle
ready
initializing
countdown
running
waiting
verifying
completed
stopping
stopped
error
```

네트워크에는 내부 상태 문자열을 그대로 보내지 않고 다음 축약 상태로 변환한다.

```text
설정 미완료
실행 준비 완료
초기 위치 이동 중
모션 시작 대기
모션 실행 중
반복 대기
정지 중
완료
오류
```

`bridge_instance_id`, `project_generation`, `operation_generation`은 로컬 상태 경계
확인에 사용한다. 네트워크 상태 순서와 중복 실행 방지에는 다음 전용 식별자를
사용한다.

- `coordination_boot_id`: 연동 노드 실행 세션.
- `coordination_sequence`: 해당 세션의 상태 순서.
- `network_operation_id`: 하나의 네트워크 제어 작업.
- `program_session_id`: 상위 로컬 프로그램 재시작을 구분하는 불투명 식별자.

- `bridge_instance_id` 변경은 상위 프로그램 재시작으로 판단하고 이전 준비·완료
  상태를 폐기한 뒤 새 `program_session_id`를 발급한다.
- `project_generation` 변경은 프로젝트 또는 실행 설정 경계 변경으로 판단하고
  이전 실행 준비 상태를 폐기한다.
- 로컬 `project_generation`, `operation_generation`, `context_id` 값 자체는 다른
  컴퓨터에 공유하지 않는다.

## 8. 공유하지 않는 데이터

- 프로젝트 ID와 프로젝트명.
- 프로젝트 파일과 프로젝트 선택 상태.
- 모터 설정값과 모터축 설정 파일.
- 모션 파일 내용과 모션축 매핑.
- 모션 스튜디오 레이어·포인트·편집 데이터.
- 실제 위치·속도·토크 명령값.
- 다른 컴퓨터의 로컬 파일 경로.
- 로컬 `project_generation`, `operation_generation`, `context_id`.
- 자동 반복에 등록된 모션 파일명과 파일 해시.

각 컴퓨터의 프로젝트가 서로 달라도 연동할 수 있으며 프로젝트 동일성은 비교하지 않는다.

## 9. 제어 대상

연동 제어는 모션 스튜디오가 아니라 `모션 실행`의 실제 구동 절차만 대상으로 한다.

모션 작업과 실제 실행의 역할은 다음과 같이 고정한다.

```text
모션 스튜디오
모션 생성 → 녹화 → 레이어·포인트 편집 → 미리보기 → 최종 모션 파일 저장
                                                        ↓
모션 실행
최종 모션 파일 선택 → 모션축 설정 확인
                      → 실행 시작
                      → 로컬 안전검사
                      → 전체 초기위치 이동
                      → 시작 대기
                      → 최종 파일 그대로 재생
```

- 모션 스튜디오는 모션 생성·편집·저장 영역이다.
- 모션 실행은 저장된 최종 모션 파일의 실제 구동 영역이다.
- 모션 실행은 최종 모션 파일과 적용된 모션축 설정만 사용한다.
- 모션 실행 중 MIDI 입력으로 모션값·속도·축 출력을 변경하지 않는다.
- 모션 실행 중 MIDI 시작·정지·선택 명령을 받지 않는다.
- MIDI 제어는 모션 스튜디오의 녹화·제작 영역에만 사용한다.
- 네트워크 연동은 실행 시작·정지 같은 고수준 요청만 전달하며 모션값을 전달하거나
  최종 모션 파일 내용을 변경하지 않는다.

| 연동 명령 | 로컬 실행 기능 |
|---|---|
| 실행 준비 확인 | 선택된 최종 모션·모션축 설정·모터·안전조건 확인 |
| 1회 모션 실행 | 로컬 검사·전체 초기위치 이동·시작 대기·최종 모션 재생 |
| 초기위치 이동 | 점검·수동 준비를 위한 모션 실행의 초기위치 이동 |
| 초기위치 이동 정지 | 진행 중인 초기위치 이동 정지 |
| 모션 정지 | 실행 중인 모션 정지 |
| 상태 다시 전송 | 현재 상태 즉시 갱신 |

- 현재 `모션 실행 시작`은 초기 위치 이동부터 파일 재생까지 한 작업으로 소유한다.
- `초기위치 이동` 후 `1회 모션 실행`을 연속 호출하면 초기 위치 이동이 두 번
  실행될 수 있으므로 기본 연동 절차에서 두 명령을 연속 사용하지 않는다.
- 기본 연동 실행은 `실행 준비 확인 → 1회 모션 실행` 순서로 한다.
- 별도 `초기위치 이동`은 점검 또는 모터 위치 준비만 필요할 때 사용한다.
- 중앙 컴퓨터는 위치값, 모션 파일명 또는 프로젝트 ID를 전달하지 않는다.
- 각 컴퓨터 사용자가 로컬 프로젝트에서 최종 모션 파일과 모션축 설정을 미리 선택한다.
- 원격 요청은 고수준 실행 요청이며 실제 실행 전 해당 컴퓨터가 로컬 안전조건을 다시 검사한다.
- 요청 결과는 수신, 검증 중, 승인, 거부, 실행 시작, 진행 중, 완료, 실패,
  사용자 취소 및 안전 차단으로 구분한다.

### 9.1 모션 실행 제어권 전달

네트워크 PC 연동은 제어권의 전달과 검증만 담당한다. 실제 동시 시작과 반복
주기는 `멀티 PC 동기 실행`이 결정한다.

```text
하위 제어권
각 컴퓨터의 1회 실행·로컬 자동 반복

상위 제어권
멀티 PC 동기 실행의 준비·시작·반복·정지
```

- 한 컴퓨터의 모션 실행 제어권은 하위 또는 상위 중 하나만 소유한다.
- 상위 제어권은 컴퓨터 전체가 아니라 `모션 실행`에만 적용한다.
- 상위 제어권 중에도 모션 스튜디오, 파일 관리, 상태 확인, 오류 확인과 설정
  화면을 전역으로 차단하지 않는다.
- 현재 실행에 사용하는 모션 파일과 모션축 설정은 준비 완료 시점의 실행
  스냅샷으로 고정한다.
- 실행 중 변경된 설정은 현재 실행에 반영하지 않고 다음 준비 확인에서 검사한다.
- 같은 모터에 조그, 위치 이동, Servo OFF 같은 다른 구동 명령을 동시에 보내는
  행위는 기존 단일 모터 제어 통로와 안전조건으로 차단한다.
- 로컬 긴급정지와 안전 정지는 제어권과 관계없이 항상 우선한다.
- 중앙 컴퓨터는 실제 모터값을 전송하지 않는다. 각 컴퓨터의
  `motion_run_manager`가 기존 `motion_system` 통로로 실행한다.

## 10. 연동에서 제외하는 제어

- 모션 스튜디오 녹화·편집·저장.
- 프로젝트 선택·변경.
- 모터 설정 수정·적용.
- 모터 검색.
- 모션 파일과 모션축 설정의 원격 선택.
- Servo ON/OFF.
- 프로그램 재시작과 모터 제어 재시작.
- 조그와 축별 위치 명령.
- Servo 오류 정책 변경.
- 긴급정지 해제와 안전 차단 해제.
- 자동 반복 설정 변경.
- 로컬 자동 반복 원격 시작.
- 자동 반복 재시작 후 자동 재개 설정.

모션 정지는 허용하지만 안전 차단 해제는 각 컴퓨터의 로컬 조작으로만 수행한다.

현재 로컬 자동 반복 기능은 프로젝트별로 저장되며 프로그램 재시작 후 다시 시작할
수 있다. 네트워크 연동은 이 설정을 변경하거나 로컬 자동 반복을 원격 시작하지
않는다.

멀티 PC 반복은 로컬 자동 반복을 원격 조작하는 기능이 아니다. 상위 모션 실행
제어권을 획득한 `멀티 PC 동기 실행`이 별도 작업으로 수행한다. 상위 제어권 동안
로컬 자동 반복 설정은 유지하되 실행만 보류하며, 상위 제어권 반환 후 자동으로
재개하지 않는다.

## 11. 기본 사용자 절차

1. 각 컴퓨터의 웹을 연다.
2. `장비 연동 상태`에서 연동 모드를 선택한다.
3. 한 컴퓨터를 중앙 역할로 지정한다.
4. 연동 참여 대상 컴퓨터를 확인한다.
5. 전체 준비 상태 확인을 요청한다.
6. 각 컴퓨터가 로컬 설정·모터·안전조건을 검사한다.
7. `1회 모션 실행`을 요청한다.
8. 각 컴퓨터가 로컬에서 전체 초기 위치 이동을 실행한다.
9. 각 컴퓨터가 시작 대기 후 등록된 최종 모션 파일을 재생한다.
10. 실행 진행 상태와 완료·오류를 확인한다.
11. 필요하면 개별 또는 전체 모션 정지를 요청한다.

별도 초기 위치 확인이 필요한 경우에만 다음 보조 절차를 사용한다.

```text
실행 준비 확인 → 초기위치 이동 → 완료 확인
```

이후 `1회 모션 실행`을 요청하면 안전을 위해 초기 위치 이동을 다시 수행한다.

## 12. 장애 처리

- 중앙 컴퓨터 종료: 로컬 기능 유지, 새로운 연동 명령 차단.
- 네트워크 단절: 로컬 기능 유지, 해당 컴퓨터를 연결 끊김으로 표시.
- 다른 컴퓨터 오류: 정상 컴퓨터의 로컬 기능에 영향 없음.
- 연동 노드 오류: 웹·Supervisor·Motor Manager 유지.
- 연동 노드 재시작: 이전 상태를 폐기하고 새 `coordination_boot_id`로 상태 재등록.
- 상위 프로그램 재시작: 이전 완료 상태를 폐기하고 새 `program_session_id`로
  상태 재등록.
- 프로젝트·모션 선택 변경: 이전 초기위치 완료·모션 완료 상태 폐기.
- 상위 프로그램의 `bridge_instance_id` 변경: 이전 준비·실행 결과 폐기.
- 로컬 `project_generation` 또는 실행 컨텍스트 변경: 이전 준비 완료 상태 폐기.
- 상태 수신 중단: 초기 기준 3~5초 후 연결 끊김으로 판정.
- 순서가 뒤바뀐 상태:
  `coordination_boot_id + coordination_sequence`로 폐기.
- 중복 실행 요청: `network_operation_id`로 한 번만 실행.
- 모순 상태: 임의로 선택하지 않고 상태 충돌로 표시.

네트워크 단절만으로 로컬 프로그램 전체를 차단하지 않는다.
이미 수락된 로컬 동작은 해당 컴퓨터의 로컬 안전조건과 사용자 조작으로 관리한다.
1차 개발에서 원격 실행은 1회 모션으로 제한하므로 중앙 컴퓨터가 종료되어도
수락된 현재 모션만 완료한 뒤 정지한다.

## 13. 전역 설정

연동 설정은 프로젝트 데이터와 분리된 전역 설정으로 관리한다.

```text
config/motion_coordination.yaml
```

예상 항목:

```yaml
machine_id: machine-a
display_name: PC A
role: coordinator
mode: status
coordinator_url: http://172.16.21.10:8010
max_computers: 32
auth_token_file: config/motion_coordination.token
allowed_coordinator_ids:
  - machine-a
```

- `machine_id`는 컴퓨터별로 중복되지 않아야 한다.
- IP 주소는 고정 IP 또는 DHCP 예약을 권장한다.
- 연동 설정과 프로젝트 데이터 사이에 대체값·복사·병합 경로를 만들지 않는다.
- 인증 토큰은 프로젝트 파일과 분리하며 상태 응답이나 로그에 기록하지 않는다.
- 연동 명령은 인증 토큰 또는 요청 서명, 허용 중앙 ID, 요청 시각,
  `network_operation_id`를 모두 검증한다.
- 기존 웹의 모션 실행 API를 외부 PC가 직접 호출하게 하지 않는다.
- `motion-coordination.service`는 `motion-control.service`와
  `motion-motor.service`의 필수 의존 서비스로 등록하지 않는다.
- 연동 서비스가 실패하거나 재시작되어도 로컬 웹과 모터 제어 서비스는 유지한다.

## 14. 개발 순서

현재 우선 개발 대상은 1~7단계의 `네트워크 상태 연동`이다. 각 단계의 검증이
끝나기 전에는 다음 단계와 멀티 PC 동기 실행 코드를 함께 활성화하지 않는다.

1. 현재 로컬 상태를 외부용 축약 상태로 변환하는 순수 변환기와 계약 테스트.
2. 네트워크 식별자, 순서, 중복 요청 방지와 인증 계약 확정.
3. 상태 공유 전용 `motion_coordination_node`와
   `motion-coordination.service` 구현.
4. `연동 끔`, `상태 공유`, `연동 참여` 구현.
5. 중앙 역할 수동 지정, 중앙 중복 차단 및 권한 폐기 구현.
6. 기존 웹에 `장비 연동 상태` 화면 추가.
7. 2대 컴퓨터로 상태 공유, 프로그램 재시작, 프로젝트 변경, 네트워크 단절 검증.
8. 모션 실행 준비 확인 연동.
9. `1회 모션 실행`과 모션 정지 연동.
10. 점검용 초기위치 이동과 초기위치 이동 정지 연동.
11. 4대, 16대, 32대 상태 부하 검증.
12. 멀티 PC 동기 실행에 필요한 제어권 획득·반환과 실행 명령 전달 계약 검증.
13. 동시 시작과 반복 주기 계산은 `MULTI_PC_MOTION_SCHEDULER_PLAN.md`에 따라
    별도 구현.

단계 구분:

| 단계 | 개발 범위 | 완료 조건 |
|---|---|---|
| 1차 | 상태 변환·통신·인증 | 단일 PC 코드 검증과 인증 실패 테스트 통과 |
| 2차 | 연동 모드·중앙 역할·웹 상태 화면 | 2대 PC 상태 공유와 단절·재시작 검증 |
| 3차 | 1회 실행 준비·실행·정지 전달 | 로컬 실행과 프로젝트 격리 검증 |
| 4차 | 상위 모션 실행 제어권 | 로컬 실행 충돌과 제어권 반환 검증 |
| 5차 | 멀티 PC 동기 실행 | 별도 개발안의 동시 시작·반복 검증 |

## 15. 검증 기준

- 서로 다른 두 개 이상의 프로젝트로 프로젝트 데이터 격리를 검증한다.
- 컴퓨터별 프로젝트·모터·모션 설정이 다른 상태를 검증한다.
- 연동 끔·상태 공유·연동 참여를 각각 검증한다.
- 중앙 역할 중복과 중앙 전환 실패를 검증한다.
- 상태 지연·순서 역전·중복·오프라인을 검증한다.
- 연동 노드 종료 후 로컬 웹·모터·모션 기능이 유지되는지 검증한다.
- `1회 모션 실행`이 모션 스튜디오가 아닌 모션 실행 경로를 사용하고
  초기 위치 이동·시작 대기·등록 파일 재생을 한 번씩 수행하는지 검증한다.
- 점검용 초기위치 이동과 1회 모션 실행을 연속 요청했을 때 초기 위치 이동이
  다시 수행된다는 사실을 UI와 결과에 명확히 표시하는지 검증한다.
- `/api/status` 전체 응답, 프로젝트 ID, 모션 파일명, Motion ID, 위치값이
  네트워크 상태에 포함되지 않는지 검증한다.
- 인증 실패, 허용되지 않은 중앙 ID, 만료 요청, 중복 `network_operation_id`를
  각각 차단하는지 검증한다.
- `bridge_instance_id`, 프로젝트 실행 컨텍스트 또는 프로젝트 세대 변경 후 이전
  준비 완료 상태가 폐기되는지 검증한다.
- 원격 제어에서 로컬 자동 반복 시작과 설정 변경이 차단되는지 검증한다.
- 상위 제어권 중 로컬 모션 실행만 거부되고 모션 스튜디오, 파일 관리, 상태 확인,
  오류 확인이 불필요하게 차단되지 않는지 검증한다.
- 상위 제어권 반환 후 로컬 자동 반복이 임의로 자동 재개되지 않는지 검증한다.
- 자동 테스트, 다중 프로세스 실행 검증, 다중 PC 실물 검증을 구분해 기록한다.

## 16. 현재 상태

- 본 문서는 확정된 개발 방향을 저장한 계획 문서다.
- 네트워크 PC 상태 공유와 제한 제어는 아직 구현하지 않았다.
- 현재 코드에는 다음 기반 기능이 구현되어 있다.
  - 프로젝트별 실행 컨텍스트와 `project_generation` 경계.
  - 취소된 모션 스튜디오 작업을 구분하는 `operation_generation`.
  - 모션 실행 준비 검사, 초기위치 이동, 1회 실행, 정지 API.
  - 모션 실행의 초기 위치 이동·시작 대기·파일 재생 단일 순서.
  - 실행 단계, 진행률, 반복 대기와 오류 상태.
  - 프로젝트별 자동 반복 설정과 모션·매핑 파일 해시 검증.
  - `motion-control.service`와 `motion-motor.service` 분리.
  - `ROS_LOCALHOST_ONLY=1`.
- 다음 기능은 아직 구현되지 않았다.
  - `motion_coordination_node`와 `motion-coordination.service`.
  - 연동 전용 상태 계약, 인증 API와 전역 설정.
  - 연동 끔·상태 공유·연동 참여.
  - 중앙 역할 수동 지정과 중복 중앙 차단.
  - 기존 웹의 `장비 연동 상태` 화면.
  - 네트워크 제어 중복 방지와 다중 PC 검증.
- 다음 개발 시작점은 상태 변환 계약과 인증을 포함한 1차 네트워크 상태 연동이다.
- 멀티 PC 동기 실행은 네트워크 상태 연동 검증 전에는 구현하거나 활성화하지 않는다.
