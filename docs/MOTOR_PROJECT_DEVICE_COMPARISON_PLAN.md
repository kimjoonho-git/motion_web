# 프로젝트 모터 검색·비교 개발안

## 상태

- 개발 상태 · 미구현
- 적용 시점 · 추후 진행
- 현재 코드 · 이 문서 작성으로 기능 변경하지 않음

## 최우선 사용자 목표

1. 현재 프로젝트의 모터 설정 완료
2. 현재 프로젝트의 모션축 설정 완료
3. MIDI 입력으로 실제 모터 구동

모터 검색과 설정 기능은 위 순서를 방해하지 않고, 사용자가 웹 화면에서 완료할 수 있어야 한다.

## 사용자에게 표시할 장치 정보

- 모터 모델
- 시리얼 번호
- 축 번호
- 축 이름
- 프로젝트 설정과 검색 결과의 비교 상태

Vendor ID, Product Code, Revision, EEPROM Alias, Slave Position 등 통신에 필요한 값은 내부에 보관한다. 사용자가 직접 입력하지 않는다.

## 프로젝트 설정과 검색 결과의 비교항목

- EEPROM Alias · 프로젝트에 저장된 장치 주소와 검색값 비교
- Slave Position · 프로젝트에 저장된 EtherCAT 연결 순서와 검색값 비교
- 시리얼 번호 · 실제 모터 고유 식별
- 모터 모델 · 동일 장치 종류인지 확인
- 모터 개수 · 신규 모터와 미검색 모터 확인

### 비교 순서

1. EEPROM Alias가 0이 아니면 Alias로 장치 후보를 찾는다.
2. EEPROM Alias가 0이면 시리얼 번호로 장치를 찾는다.
3. 찾은 장치의 시리얼 번호와 모터 모델을 확인한다.
4. Slave Position 변경 여부를 확인한다.
5. 프로젝트에 없는 신규 모터와 검색되지 않은 기존 모터를 확인한다.

EEPROM Alias와 Slave Position은 반드시 비교하지만, 단독 고유 식별값으로 사용하지 않는다. 현재처럼 모든 Alias가 0이면 시리얼 번호를 고유 식별값으로 사용한다.

## 프로젝트 모터 설정 파일이 없을 때

1. 사용자가 `AC Servo 검색` 또는 `전체 모터 검색`을 실행한다.
2. 물리 검색 결과로 축 편집 초안을 자동 구성한다.
3. 사용자가 축 번호와 축 이름을 확인·수정한다.
4. 사용자가 프로젝트 설정 저장을 실행한다.
5. 사용자가 설정 적용 및 재시작을 실행한다.

별도의 모델 직접 입력이나 모델 확인 절차를 요구하지 않는다.

## 프로젝트 모터 설정 파일이 있을 때

검색 결과를 현재 프로젝트 파일과 비교하여 다음 상태로 표시한다.

- 일치 · Alias, Slave Position, 시리얼 번호, 모터 모델이 설정 기준과 일치
- 연결 순서 변경 · 동일 장치의 Slave Position이 변경됨
- Alias 변경 · 동일 장치의 EEPROM Alias가 변경됨
- 모델 불일치 · 동일 시리얼 번호의 모터 모델이 다름
- 신규 모터 · 프로젝트에 없는 시리얼 번호가 검색됨
- 기존 모터 미검색 · 프로젝트의 시리얼 번호가 검색되지 않음
- 비교 불가 · 모델 또는 시리얼 번호 미수신, 시리얼 번호 중복

차이가 있으면 추가·변경·누락 내용을 사용자에게 알린다. 사용자가 확인한 경우에만 검색 결과를 프로젝트 설정 파일에 저장한다. 취소하면 프로젝트 파일을 변경하지 않는다.

## 저장 시 데이터 유지 기준

- 동일 시리얼 번호 · 기존 축 번호와 축 이름 유지
- 동일 장치의 연결 순서 변경 · 현재 검색된 내부 연결값으로 갱신
- 신규 시리얼 번호 · 새 축으로 추가
- 기존 모터 미검색 · 제거 예정으로 표시 후 사용자 확인
- 모델 또는 시리얼 번호 비교 불가 · 자동 저장 및 실행 적용 차단

## UI 단순화 방향

- `실제 장치 식별`을 `모터 모델·시리얼`로 변경
- Vendor/Product/Revision/Alias/Slave 상세값은 기본 표에서 숨김
- `모델·운전 프로필 설정` 제거
- 사용자의 명판 모델 직접 입력 제거
- 프로젝트 설정이 없을 때 `선택 축 추가` 단계 제거
- 기본 흐름을 `검색 → 비교·편집 → 저장 → 적용`으로 통일

## 검증 순서

1. 프로젝트 설정 없음 · 검색 → 저장 → 재조회
2. 동일 프로젝트 설정 · 재검색 → 전체 일치
3. Slave Position 변경 · 연결 순서 변경 감지
4. Alias 변경 · Alias 변경 감지
5. 신규 모터 추가 · 신규 시리얼 감지
6. 기존 모터 분리 · 미검색 시리얼 감지
7. 모델 변경 · 동일 시리얼의 모델 불일치 감지
8. 프로젝트 두 개 · 설정과 검색 비교 결과 격리
9. 설정 적용 및 재시작 · 현재 프로젝트 파일만 사용
10. 모션축 설정 완료 → MIDI 입력 → 실제 모터 구동

각 검증은 코드 검증, 실행 검증, 실물 검증을 구분하여 기록한다.
