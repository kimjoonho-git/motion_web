# Motion Web 전체 동작 흐름

- 문서 기준일: 2026-08-04
- 대상: Motion Web · Motion Control Studio · 네트워크 PC 연동 · 멀티 PC 동기 실행
- 원칙: 각 PC의 프로젝트·모션·모터 데이터는 로컬에서 관리하고 PC 사이에는
  축약 상태와 고수준 실행 명령만 전달한다.

## 1. 전체 구조

```text
사용자 브라우저
    │ HTTP :8000
    ▼
Motion Web
    ├─ 프로젝트·모션 선택
    ├─ 모션 스튜디오 편집
    ├─ 모션 실행 화면
    └─ 장비 연동 상태
           │
           ▼
motion_coordination_node :8010
    ├─ PC 상태 공유
    ├─ HMAC 인증
    ├─ 중앙 PC 권한 확인
    ├─ 실행 제어권 lease
    ├─ 예약 시작 시각 계산
    └─ 다른 PC에 고수준 명령 전달
           │
           ▼
각 PC의 motion_run_manager
    ├─ 로컬 프로젝트·모션축 설정 검사
    ├─ 초기위치 이동
    ├─ 예약 시각 대기
    ├─ 로컬 모션 파일 재생
    └─ 정지·반복·결과 기록
           │
           ▼
motion_supervisor
    ├─ 명령 충돌 차단
    └─ 안전 상태 확인
           │
           ▼
motion_system
    └─ 각 PC에 연결된 AC Servo·Dynamixel 제어
```

네트워크 연동은 모터 명령을 직접 발행하지 않는다. 모든 실제 모터 명령은
`motion_run_manager → motion_supervisor → motion_system` 단일 통로를 사용한다.

## 2. 부팅과 서비스

사용자 서비스 설치 후 다음 서비스가 재부팅 시 실행된다.

- `motion-control.service`: Web UI·Web Bridge·모션 실행 프로그램
- `motion-motor.service`: Motor Manager
- `motion-coordination.service`: PC 상태·실행 연동

사용자 웹은 `http://<해당 PC IP>:8000`으로 접속한다. PC별 IP가 다르면 각 PC가
동일한 `8000`, `8010` 포트를 사용해도 충돌하지 않는다.

## 3. 각 PC의 로컬 준비

각 PC는 자기 프로젝트에서 다음 항목을 준비한다.

1. 프로젝트 선택
2. 최종 모션 파일 선택
3. 모션축 설정 적용
4. 모터 연결·Servo·안전 상태 확인
5. `장비 연동 상태`에서 연동 모드와 역할 설정

처음 연결할 때는 수동으로 peer URL·허용 IP·HMAC 키를 편집하지 않는다.

1. 중앙 PC 웹의 `장비 연동 상태 → 간편 PC 연동`에서 PC ID를 확인하고
   `연동 코드 생성`을 누른다.
2. 참여 PC의 같은 화면에 중앙 PC IP와 표시된 8자리 코드를 입력하고
   `이 PC 연결`을 누른다.
3. 양쪽 전역 설정과 암호화 키가 저장되고 `motion-coordination.service`가
   설치된 PC에서는 서비스 재시작을 요청한다.
4. 두 PC는 안전한 `상태 공유` 모드로 시작한다. 고수준 실행 연동은 사용자가
   별도로 `연동 참여` 모드와 역할을 확인한 뒤 사용한다.

연동 코드는 5분·1회용이며 네트워크로 직접 전송하지 않는다. 연동 설정은
`motion_projects`가 아닌 전역 `config/motion_coordination*.yaml`에 저장된다.

- 설정과 자격증명 저장은 PC별 파일 잠금으로 직렬화한다.
- 두 파일 저장 중 오류가 발생하면 중단 기록을 사용해 이전 두 파일을 복구한다.
- 기존 peer가 있으면 PC ID를 변경하지 않는다.
- 같은 peer를 재연동하면 새 URL·키로 교체하고 사용하지 않는 이전 `/32` IP를
  허용 목록에서 제거한다.
- 양쪽 파일 저장 후 서비스 설치·재시작이 실패하면 `부분 완료`로 표시한다.

PC별 프로젝트와 모션 파일은 달라도 된다. 프로젝트 전환 시 이전 프로젝트의
준비·실행 결과는 새 프로젝트에 적용하지 않는다.

## 4. 상태 공유와 데이터 경계

`motion_coordination_node`는 등록된 PC에 다음 축약 상태를 주기적으로 전달한다.

- 프로그램 정상·오류
- 모터 전체·온라인·오류 축 수
- 안전 차단 상태
- 모션 준비·초기위치 이동·시작 대기·실행·완료 상태
- 연동 모드·역할
- 프로그램·프로젝트 경계를 구분하는 불투명 세션 ID

다음 데이터는 공유하지 않는다.

- 프로젝트 ID·프로젝트명
- 모션 파일명·모션 데이터
- 모션축·모터 설정값
- 위치·속도·토크 명령값
- 모션 스튜디오 편집 데이터

## 5. 연동 모드와 역할

| 모드 | 상태 공유 | 실행 명령 |
|---|---:|---:|
| `연동 끔` | 차단 | 차단 |
| `상태 공유` | 허용 | 차단 |
| `연동 참여` | 허용 | 인증된 중앙 PC만 허용 |

- `중앙 PC`: 전체 준비 확인과 고수준 실행 명령 전달
- `참여 PC`: 설정에 지정된 중앙 PC의 인증된 명령만 수신
- 중앙 역할이 중복되면 실행 권한을 차단한다.

## 6. 일반 원격 실행

```text
중앙 PC의 1회 모션 실행 요청
    → 각 PC의 로컬 프로젝트·파일·안전조건 확인
    → 각 PC의 전체 초기위치 이동
    → 시작 대기
    → 각 PC의 로컬 최종 모션 파일 1회 재생
```

`초기위치 이동`은 점검용 별도 기능이다. 이후 `1회 모션 실행`을 요청하면 안전을
위해 초기위치 이동부터 다시 수행한다.

정지 명령은 다음과 같이 구분한다.

- `모션 정지`: 현재 동작 즉시 정지
- `초기위치 이동 정지`: 진행 중인 초기위치 이동 정지
- `현재 회차 후 정지`: 동기 반복의 다음 회차 시작 차단

## 7. 동기 실행

동기 실행의 목표 절차는 다음과 같다.

1. 각 PC의 실행 준비 확인
2. 모션 재생시간·초기위치 이동 예상시간 수집
3. chrony 시간 동기화와 허용 오차 확인
4. 네트워크 모션 실행 제어권 획득
5. 미래 UTC 공통 시작 시각 계산
6. 각 PC의 초기위치 이동
7. 공통 시작 시각까지 monotonic 기준으로 대기
8. 같은 예약 경계에서 각 PC의 로컬 모션 재생
9. 요청 시각·실제 시작 시각·시작 오차 기록

예약 시각이 지났거나 시간 동기화 오차가 허용 범위를 넘으면 늦게 시작하지 않고
해당 실행을 거부한다.

## 8. 동기 반복

```text
공통 반복 주기 = 참여 PC의 최장 모션시간 + 공통 대기시간
```

공통 주기는 20ms 단위로 올림한다. 다음 회차는 직전 완료시각이 아니라 다음 식의
절대 경계로 계산한다.

```text
반복 N 시작 = 최초 시작 시각 + N × 공통 반복 주기
```

짧은 모션은 최종 목표값을 유지하면서 다음 공통 시작 경계까지 기다린다.

## 9. 실행 제어권

- `로컬`: 해당 PC의 로컬 1회 실행·자동 반복·초기위치 이동 허용
- `네트워크`: 중앙 PC가 멀티 PC 동기 실행 제어권 보유

네트워크 제어권 중 충돌하는 로컬 실행만 차단한다. 모션 스튜디오 편집, 파일·상태·
오류 확인과 안전 정지는 유지한다. 제어권은 제한시간이 있는 lease이며 중앙 PC
상태가 끊기면 갱신하지 않고 다음 반복을 차단한다.

## 10. 중복·재시작·프로젝트 보호

- 모든 네트워크 실행은 고유 `network_operation_id`를 사용한다.
- 처리한 작업 ID는 로컬 전역 런타임 영역에 기록해 재시작 후 재실행을 차단한다.
- `coordination_boot_id + sequence`로 순서 역전 요청을 폐기한다.
- 프로그램 재시작 시 이전 준비 상태를 폐기한다.
- 프로젝트 전환 시 이전 프로젝트에서 시작한 비동기 결과를 폐기한다.
- 등록되지 않은 PC, 잘못된 HMAC, nonce 재사용과 만료 요청을 차단한다.

## 11. 안전 경계

긴급정지와 안전 정지는 네트워크 실행 제어권보다 항상 우선한다. 실제 실행 전과
실행 중에는 기존 모터 연결, Servo 오류, 안전 차단, 명령 소유권, 목표 범위와
최종 위치 도달 조건을 사용한다.

## 12. 검증 상태

- 코드·계약·빌드·자동 테스트: 확인됨
- 서로 다른 두 프로젝트의 데이터 격리: 코드 검증 확인됨
- 실제 여러 PC의 상태 공유·단절·재시작: 실물 미검증
- 실제 모터의 동시 시작·10ms 목표 오차·최종 위치 유지: 실물 미검증

세부 계약과 개발 상태는 `NETWORK_PC_COORDINATION_PLAN.md`와
`MULTI_PC_MOTION_SCHEDULER_PLAN.md`를 함께 확인한다.

## 13. 현재 코드 대조 검토

### 13.1 확인된 구조

- `8000` 사용자 웹과 `8010` PC 연동 통신이 분리되어 있다.
- 상태·준비·실행 요청은 HMAC, nonce, sequence와 등록 peer를 검사한다.
- 네트워크 요청은 프로젝트명·파일명·모션값을 전달하지 않는다.
- 각 PC는 자기 활성 프로젝트와 모션축 설정으로 `motion_run_manager`를 호출한다.
- 프로젝트 세대가 바뀌면 Web Bridge가 이전 준비·실행 응답을 폐기한다.
- 상태·준비·일반 제어 송수신에는 최대 16개 병렬 요청 제한이 있다.
- 실제 모터 명령은 기존 `motion_supervisor → motion_system` 경로를 사용한다.
- 네트워크 `1회 실행`과 `초기위치 이동`은 유효한 실행 lease가 있어야 한다.
- 연동 노드는 종료 신호를 정상 종료로 처리하고 중복 `rclpy.shutdown()`을 피한다.

### 13.2 최우선 보완 대상

1. **초기위치 완료 확인 후 시작 명령 분리**
   - 현재 동기 실행은 예상 초기위치 시간으로 미래 시작 시각을 계산한 뒤 바로
     `START_AT`을 전달한다.
   - 각 PC가 실제 초기위치 이동을 완료한 `ARMED` 상태를 중앙 PC가 모두 확인하는
     단계가 없다.
   - 한 PC의 초기위치 이동이 예상보다 늦거나 실패하면 다른 PC만 예약 시각에
     시작할 수 있다.

2. **완료 · 부분 예약 성공의 전체 취소**
   - 일부 PC가 `START_AT`을 수락하고 다른 PC가 거부하면 모든 PC에
     `CANCEL_BEFORE_START`를 먼저 전달한다.
   - 예약 취소 전달이 끝난 뒤 lease를 반환한다.

3. **반복 시각의 단일 monotonic 기준 유지**
   - 첫 시작은 UTC 남은 시간을 monotonic 마감시각으로 변환한다.
   - 다음 반복은 매회 UTC 벽시계와 `time.time()`으로 남은 시간을 다시 계산한다.
   - 최초 수신 시 한 번 만든 monotonic 기준에 `N × 공통 주기`를 더하는 구조로
     통일해야 벽시계 변경과 재계산 오차 영향을 차단할 수 있다.

4. **실행 중 오류의 즉시 전체 정지**
   - 중앙 PC는 참여 PC 중 하나가 `error`여도 다른 PC가 `running`이면 현재 회차가
     끝날 때까지 전체 오류 처리를 미룬다.
   - 즉시 정지가 필요한 모터·안전 오류와 회차 후 정지가 가능한 일반 오류를
     구분해 전파해야 한다.

### 13.3 다음 보완 대상

5. **동기 준비 요청 병렬화와 웹 제한시간 일치**
   - 일반 `전체 실행 준비 확인`은 병렬이지만 동기 실행 내부 준비 확인은 peer를
     순차 호출한다.
   - peer당 제한시간이 4초이고 Web Bridge 제어 응답 제한시간이 18초이므로
     4·16·32대 실제 연결에서는 화면이 먼저 시간 초과될 수 있다.

6. **lease와 반복 경계의 원자적 검사**
   - lease 만료 시 연동 노드가 `현재 회차 후 정지`를 전달한다.
   - `motion_run_manager`가 다음 반복 직전에 lease 유효성을 직접 확인하지 않아
     만료와 반복 경계가 겹치면 다음 회차가 먼저 시작될 가능성이 있다.

7. **시간 동기화 재검사**
   - chrony 오차는 준비 시점에만 검사한다.
   - 예약 시작 직전과 장시간 반복 중 허용 오차를 다시 검사하는 경로가 없다.

8. **완료 · 실행 중 제어권 수동 반환 제한**
   - 동기 실행 중에는 화면의 `제어권 반환`을 비활성화한다.
   - 화면 상태 갱신 전 요청도 연동 노드에서 다시 검사해 거부한다.

9. **부분 완료 · 작업 기록 손상 시 실패 방식**
   - `network_operation_id` 기록 파일이 없으면 새 이력으로 시작한다.
   - 읽기 실패·JSON 손상·잘못된 최상위 형식은 실행을 차단한다.
   - 운영용 백업·복구 절차와 화면 안내는 실제 다중 PC 검증 전에 추가한다.

10. **실제 규모 검증 범위 구분**
    - 현재 4·16·32대 검증은 주기 계산과 제한된 병렬 작업 시뮬레이션이다.
    - 실제 HTTP 지연, 패킷 손실, chrony 편차, 프로세스 재시작과 모터 부하를 포함한
      다중 PC 실행 검증은 남아 있다.
