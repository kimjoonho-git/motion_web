## 왜 이 점검을 했나

2026-09-18 하루에 난 문제들이 **전부 같은 모양**이었습니다.

| 겪은 일 | 실제 원인 |
|---|---|
| 프로젝트 바꿨다 돌아오니 MIDI 가 안 됨 | 프로젝트가 MIDI·모터·스튜디오를 다 끌고 다님 |
| 모션 파일만 바꿨는데 「모션축 설정 저장 충돌」 | 한 파일에 주인이 셋인데 길이 하나였음 |
| 등록이 한 번 실패하니 버튼이 영영 꺼짐 | 화면이 제 나름대로 판단하다 제 발을 묶음 |
| 사용법 화면이 모든 탭에 나옴 | 새 규칙이 남의 규칙을 덮어씀 |

하나씩 고치면 또 다른 얼굴로 나옵니다. 그래서 뿌리를 적어 둡니다.

## 1. 「움직이는 중」에 집을 준다

**상태** : ✅ 끝남 (2026-09-18)

**무엇이 문제인가**

`{'running', 'verifying'}` 가 다섯 파일에 **손으로** 적혀 있습니다.

```
bridge_helpers.py:43            midi_control_node.py:1113
playback_session.py:161,183,217 recording_session.py:173
group_session.py:52             ← 여기만 'motion_completed' 가 더 붙어 있다
```

`run_state.py` 가 있지만 **다른 개념**의 주인입니다.

| 개념 | 뜻 | 주인 |
|---|---|---|
| 멈춰 있지 않다 | `initializing` **포함** | `run_state.is_running` |
| 지금 축이 움직인다 | `initializing` **제외** | **없음** ← 이것 |

**무슨 일이 생기나**

새 상태가 하나 생기면 다섯 곳을 고쳐야 하고, 빠뜨린 곳만 조용히 틀립니다.
`group_session` 이 이미 다르게 적고 있습니다 — 의도인지 실수인지 코드만
봐서는 알 수 없습니다.

**어떻게 고치나**

`run_state.py` 에 `is_moving()` 을 두고 다섯 곳이 부릅니다.
`group_session` 의 차이는 그 자리에서 이유를 적거나 없앱니다.

**크기** : 작음 · **위험** : 낮음

**한 일** : `run_state.is_moving()` 을 만들고 다섯 곳이 부르게 했습니다.
`group_session` 의 `motion_completed` 는 **다른 질문**이라 그대로 뒀습니다.

## 1-1. 같은 목록을 두 곳에 적지 않는다

**상태** : ✅ 끝남 (2026-09-18) · 1번을 하다 같은 병이 더 보여 이어서 했습니다.

| 무엇 | 몇 곳에 | 주인 |
|---|---|---|
| 실행 컨텍스트 명령 | 세 노드가 각자 | `generation.CONTEXT_COMMANDS` |
| 스튜디오 「일하는 중」 | 세 곳 · 한 곳은 **순서까지 달랐다** | `MOTION_STUDIO_BUSY_STATES` |
| 스튜디오 「움직이는 중」 | 두 곳 | `MOTION_STUDIO_MOVING_STATES` |
| 실패 결말 | 두 곳 (이미 이름이 있었는데도) | `TERMINAL_FAILURES` |
| 「프로젝트를 먼저 선택하세요」 | **여덟 곳** · 게다가 세 가지 말로 | `paths.NO_PROJECT_SELECTED` |

마지막 것이 특히 나빴습니다. 같은 상황에 세 가지 말이 나왔습니다.

```
통합 프로젝트를 먼저 선택하세요
왼쪽에서 통합 프로젝트를 먼저 선택하세요
서보 에러 등급을 저장할 프로젝트를 먼저 선택하세요
로컬 프로젝트를 먼저 선택하세요
```

사용자는 다른 문제인 줄 압니다.

**곁가지로 나온 것** : 연동 브리지 시험이 **이 PC 에서 도는 연동 서비스에
붙고** 있었습니다. 그룹이 돌고 있으면 시험이 그 상태를 읽어 엉뚱하게
실패했습니다. 이제 제 손으로 세운 상태만 봅니다.

## 2. 화면은 판단하지 않는다

**상태** : 대기

**무엇이 문제인가**

같은 판정을 세 층에서 **따로** 합니다.

```
화면    버튼 비활성     제 나름의 조건
브리지  change_blocker  제 나름의 상태 집합
노드    ValueError      또 제 나름의 조건
```

`ensure_change_allowed` / `change_blocker` 호출이 **11곳**이고, 한 요청이
같은 판정을 두 번 지나는 길도 있습니다.

**무슨 일이 생기나**

2026-09-18 의 버튼 사고가 정확히 이 모양이었습니다. 화면이 제 나름대로
「편집 중」 표시를 세워 두고 저장에 실패하자, 그 표시 때문에 되돌아갈
버튼까지 꺼졌습니다. 서버는 멀쩡했는데 화면만 막혔습니다.

**어떻게 고치나**

서버가 **「왜 안 되는지」를 내려주고**, 화면은 그것을 그대로 보여줍니다.

버튼 비활성 자체는 없애지 않습니다 — 왜 안 되는지 미리 알려주는 것이
맞습니다. 없애는 것은 **화면이 스스로 계산하는 부분**입니다.

**크기** : 중간 · **위험** : 중간

## 3. project_service 를 브리지에서 떼어낸다

**상태** : 🟡 절반 · 18가지 → **5가지** (2026-09-18)

**무엇이 문제인가**

모든 서비스가 브리지 속을 직접 만집니다.

```
project_service.py          55회
scan_orchestrator.py        19회
execution_context_service   18회
manual_motor_commands       13회
```

특히 `project_service` 하나가 브리지의 **18가지 속살**을 꺼내 씁니다.

```
_execution_context 12 · _motor_config 11 · _current_project_generation 9
_motion_run_lock · _motion_run_status · _midi_monitor_store · _midi_monitor_lock
_motion_mapping_store · _motion_studio_sync · _motor_event_log · _manual · _lock
```

**무슨 일이 생기나**

프로젝트를 건드리면 MIDI·모터·스튜디오·모션 실행이 **전부 딸려 옵니다.**
그래서 프로젝트를 바꿨다 돌아오면 여기저기가 깨져 있습니다.

**어떻게 고치나**

필요한 것만 받아 쓰게 바꿉니다. 한 번에 다 하지 않고, 위의 열두 가지를
하나씩 떼어냅니다.

**크기** : 큼 · **위험** : 높음 · 전시 운영 중에는 한 번에 하나씩

### 3-1. 한 메서드가 13가지를 만지고 있었다 ✅ (2026-09-18)

18가지 중 **13가지가 한 메서드에 몰려 있었습니다** — `clear_scoped_memory`.

```python
with self.bridge._lock:
    self.bridge._motion_state = None
with self.bridge._motion_run_lock:
    self.bridge._motion_run_status = {}
with self.bridge._midi_monitor_lock:
    self.bridge._midi_monitor_status = {}
self.bridge._midi_monitor_store.clear()
...
```

프로젝트를 다루는 쪽이 브리지의 속살 13가지와 **락 3개**를 알아야 했습니다.

**고침** : 브리지가 제 것을 스스로 버립니다 (`forget_project_memory`) ·
프로젝트 쪽은 「잊어라」 한 마디만 합니다.

**남은 5가지** : `_execution_context` · `_motor_config` ·
`_current_project_generation` · `_ensure_project_mutation_allowed` ·
`_advance_project_generation` · 이것들은 **프로젝트 자체에 딸린 일**이라
성격이 다릅니다 · 다음에 볼 것은 「이 중 프로젝트의 일이 아닌 것이 있나」입니다.

**지키는 법** : `test_services_keep_their_hands_to_themselves.py` 가 서비스마다
가짓수 상한을 둡니다 · 줄이는 건 환영, 늘리면 걸립니다.

## 이미 고친 것

지운 것이 아니라 **같은 병의 지난 얼굴**입니다. 다시 나오면 여기를 보세요.

### 한 파일에 주인이 셋 (2026-09-18 고침)

`모션1.yaml` 하나에 셋이 들어 있었습니다.

```
mappings        모션축 설정 화면
midi_banks      MIDI 입력 설정 화면
motion_file_id  모션 실행 화면 (재생 등록)
```

MIDI 만 제 길이 있었고 재생 등록은 「설정 전체 저장」 길로 다녔습니다.
그래서 모션 파일만 바꿔도 모션축 설정 개정 검사에 걸렸습니다.

**고침** : 재생 등록에 제 길을 냈습니다 · 개정 번호에서도 뺐습니다.

### 연동이 둘로 갈려 있었다 (2026-09-18 고침)

「그룹 나가기」와 「지금 빠지기」가 따로 있었는데, 멈춰 있을 때는 완전히
같은 일이었습니다. 사용자가 매번 어느 쪽인지 골라야 했습니다.

**고침** : 참가·탈퇴 둘로 합쳤습니다 · 도는 중에는 못 나갑니다.

### 같은 병의 문이 넷이었다 (2026-09-18 고침)

「이 축은 빼고 돌려라」를 네 가지 방법으로 말할 수 있는데, 셋만 막혀
있었습니다. 네 번째(재생 선택 끄기)로 들어오면 모션 전체가 거부됐습니다.

**고침** : 네 번째 문도 막았습니다.
