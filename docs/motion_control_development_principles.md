# Motion Control Development Principles

> 상태: 현재 구조의 상시 개발 기준
> 과거 개발 단계와 완료 작업 기록은 포함하지 않는다.

## 1. 계층과 책임

```text
web_ui
  → motion_web_bridge
  → motion_control_studio의 상위 제어 노드
  → motion_supervisor
  → motion_system
  → 실제 모터
```

### motion_system

- EtherCAT, Servo Driver와 실제 모터 통신을 담당한다.
- 모터 상태를 발행하고 최종 모터 명령을 수신한다.
- 일반적인 상위 기능 개발이나 웹 오류 수정 대상으로 확대하지 않는다.
- 상위 계층이 `motion_system`을 우회하여 모터와 통신하지 않는다.
- 수정이 필요하면 대상과 이유를 먼저 제시하고 사용자의 명시적인 지시를 받는다.

### motion_control_studio

- 모터 상태 가공, 명령 중재, MIDI 입력, 모션 실행과 모션 스튜디오를 담당한다.
- `motion_supervisor`가 최종 모터 명령의 단일 발행자 역할을 담당한다.
- `motion_run_manager`는 모션 실행의 검사, 초기 위치 이동, 시작 대기,
  파일 재생과 반복 상태를 한 실행 순서로 관리한다.
- 조그, 동작 테스트, MIDI 모터 제어와 모션 실행의 제어권 충돌을
  `motion_supervisor`에서 중재한다.

### motion_web

- 웹 화면, HTTP API, ROS 요청 전달과 프로젝트 파일 입출력을 담당한다.
- 웹 UI는 실제 모터 명령을 생성하거나 안전조건을 최종 판정하지 않는다.
- 브라우저 상태만으로 실행 성공을 추측하지 않고 백엔드 작업 결과를 표시한다.

## 2. 모터 제어 불변조건

1. 모터 통신과 실제 제어는 `motion_system`을 단일 통로로 사용한다.
2. 최종 모터 명령은 `motion_supervisor`를 거친다.
3. 긴급정지와 안전 정지는 일반 실행 제어권보다 항상 우선한다.
4. 같은 모터에 충돌하는 두 실행 주체가 동시에 명령하지 못하게 한다.
5. 모터 상태가 제한시간 안에 갱신되지 않으면 새 구동 명령을 허용하지 않는다.
6. 위치·속도·Servo 오류와 실행 안전조건은 실제 구동 직전에 다시 검사한다.
7. UI에서 편집을 허용하는 조건과 실제 모터 구동 허용조건을 혼합하지 않는다.
8. 특정 모터 종류의 예외를 공통 상위 제어 구조에 직접 넣지 않고 어댑터나
   장치별 검사 경계에 격리한다.

## 3. 프로젝트 데이터 격리

- 설정과 작업 데이터는 현재 선택된 프로젝트를 기준으로 관리한다.
- 프로젝트별 모터 설정, 모션축 설정, 모션 파일, 레이어, 실행 설정과 캐시는
  서로 섞지 않는다.
- 다른 프로젝트의 값을 기본값이나 실패 대체값으로 사용하지 않는다.
- 프로젝트 전환 시 이전 프로젝트의 비동기 결과를 새 프로젝트에 반영하지 않는다.
- 공유 데이터는 프로젝트 데이터와 구분된 전역 설정으로 명시한다.
- 프로젝트 변경은 `프로젝트·장비 > 시스템 정보`에서만 수행한다.

프로젝트 파일은 다음 역할로 분리한다.

```text
motion_projects/<project_id>/
├─ project.json
├─ motor_axes/
├─ motion_axis_matching/
├─ motions/
├─ layers/
├─ runtime/
└─ trash/
```

- 모터 설정은 `motor_axes`의 YAML을 기준으로 관리한다.
- 모션축 설정과 MIDI 뱅크는 `motion_axis_matching`의 같은 YAML에서 관리한다.
- 최종 모션 파일과 스튜디오 레이어는 서로 독립적으로 보관한다.
- 저장 파일이 영구 원본이고 노드 메모리는 실행용 상태다.

## 4. 모터 검색과 실행 상태

- 모터 검색은 프로젝트 파일이나 이전 검색 결과가 아니라 실제 장치 응답으로 판정한다.
- 전체 모터 검색의 영구 조건은 `MOTOR_SCAN_CONTRACT.md`를 따른다.
- YAML 등록 상태, 버스 검색 결과와 런타임 피드백을 같은 의미로 표시하지 않는다.
- 검색 성공과 Motor Manager 실행 복구 성공을 별도로 검증한다.
- `systemctl` 요청 성공만으로 모터 연결 또는 복구 완료를 확정하지 않는다.
- 비동기 검색·적용·재시작 작업은 고유 작업 ID와 제한시간을 가진다.
- 작업은 `완료`, `부분 완료`, `실패` 또는 `검증 불가`로 끝나야 하며
  무기한 진행 상태를 허용하지 않는다.

## 5. 모션 제작과 실행

### 모션 스튜디오

- 모션 생성, MIDI 녹화, 레이어·포인트 편집과 합성 미리보기를 담당한다.
- 편집 결과는 저장 전 작업본과 저장 원본을 구분한다.
- 최종 모션 파일 내보내기는 사용자가 선택한 단일 레이어를 기준으로 한다.

### 모션 실행

- 사용자가 명시적으로 등록한 최종 모션 파일 한 개를 실행한다.
- 임의 파일을 자동 선택하지 않는다.
- 실행은 등록 파일 검사, 전체 초기 위치 이동, 시작 대기와 파일 재생 순서로 진행한다.
- 모션 실행에서 MIDI 값으로 모션을 변경하지 않는다.
- 자동 반복은 프로젝트별 하위 실행 기능으로 관리한다.
- 현재 실행에 사용하는 파일과 설정은 실행 준비 시점의 스냅샷으로 고정한다.

## 6. 실행 제어권

- 로컬 1회 실행과 로컬 자동 반복은 하위 모션 실행 제어권이다.
- 네트워크 동기 실행은 상위 모션 실행 제어권이다.
- 한 컴퓨터의 모션 실행 제어권은 하위 또는 상위 중 하나만 소유한다.
- 상위 제어권은 모션 실행에만 적용하고 다른 화면과 비구동 기능을 전역 차단하지 않는다.
- 상위 제어권 동안 로컬 자동 반복 설정은 유지하되 실행은 보류한다.
- 상위 제어권 반환 후 로컬 자동 반복을 임의로 자동 재개하지 않는다.
- 네트워크 연동과 동기 실행의 상세 기준은 다음 문서를 따른다.
  - `NETWORK_PC_COORDINATION_PLAN.md`
  - `MULTI_PC_MOTION_SCHEDULER_PLAN.md`

## 7. 노드와 프로세스 경계

- 서로 다른 장애 범위와 생명주기를 가진 기능은 별도 프로세스 또는 서비스로 분리한다.
- 같은 제어권과 상태를 공유하는 기능을 불필요하게 여러 노드로 나누지 않는다.
- 네트워크 연동과 멀티 PC 동기 실행은 하나의 `motion_coordination_node`에서
  상태를 소유하고 내부 모듈을 분리한다.
- `motion_coordination_node` 실패가 로컬 웹, `motion_run_manager`,
  `motion_supervisor`와 Motor Manager를 종료시키지 않게 한다.
- 새로운 노드는 기존 모터 제어 통로를 우회하지 않는다.

## 8. Git 작업 경계

- `/home/joonho_test/ros2_ws`는 `motion_web` 변경을 관리하는 상위 Git 저장소다.
- `/home/joonho_test/ros2_ws/src/motion_control_studio`는 별도 Git 저장소다.
- `/home/joonho_test/ros2_ws/src/motion_system`은 보호되는 별도 Git 저장소다.
- 사용자가 Git 대상을 지정하지 않으면 상위 `motion_web` 저장소만 대상으로 한다.
- 수정하지 않은 저장소에는 브랜치, 커밋 또는 병합을 만들지 않는다.
- `motion_system` Git 작업은 사용자가 모션시스템을 대상으로 명시한 경우에만 수행한다.
- 여러 저장소의 상태와 커밋을 하나의 결과처럼 합쳐서 보고하지 않는다.

## 9. 개발과 검증

- 새 기능은 기존 단일 책임자와 데이터 흐름을 확인한 뒤 추가한다.
- 같은 상태의 임시 저장소나 병렬 실행 경로를 덧붙이지 않는다.
- 구조 변경이 필요하면 코드 수정 전에 이유와 범위를 사용자에게 알린다.
- 비동기 결과는 작업을 시작한 프로젝트와 실행 세션이 일치할 때만 적용한다.
- 여러 기능이나 장치를 수정하면 각각 독립적으로 검증한다.
- 검증 결과는 다음과 같이 구분한다.
  - 코드 검증
  - 실행 검증
  - 실물 검증
- 실제 장비로 확인하지 않은 결과는 `실물 미검증`으로 표시한다.
- 완료 보고에는 검증 대상, 방법과 결과를 포함한다.
